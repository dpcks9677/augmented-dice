# 주사위 모서리·꼭짓점 정지 보정 구현 계획서

- 작성일: 2026-07-29
- 상태: 보류 — 결과 확정 이전 회전 문제를 방지하기 위해 구현 철회
- 범위: 주사위 투척 종료 시 안정적인 면으로 정착시키는 물리 후처리

## 1. 목적

고속 투척 뒤 주사위가 모서리 또는 꼭짓점에 거의 정지한 채 결과가 확정되는 현상을 제거한다. 실제 물리 시뮬레이션의 충돌·감쇠는 유지하되, 결과 확정 직전에만 시각적·물리적으로 안정된 면 상태를 보장한다.

게임 규칙의 난수 계산, 주사위 값 확정 규칙, 보드 STL, 투척 속도 및 중앙 낙하 연출은 변경하지 않는다.

## 2. 원인 정리

- Cannon 물리는 고정 시간 간격으로 충돌을 풀이하므로, 매우 얕은 모서리/꼭짓점 접촉이 한동안 유지될 수 있다.
- 현재 굴림은 일정 물리 시간 이후 강제로 종료될 수 있어, 자연스럽게 다음 면으로 넘어가기 직전의 자세가 결과 확정 시점에 남을 수 있다.
- 바닥 마찰·감쇠·수치 오차 때문에 현실에서 드문 준안정 상태가 화면에서는 상대적으로 자주 보인다.

## 3. 설계 원칙

1. 투척 중에는 보정하지 않는다. 충돌, 반동, 회전의 자연스러운 연출을 보존한다.
2. 속도가 충분히 낮고 종료 조건이 가까운 `SETTLING` 단계에서만 판정한다.
3. 이미 평평한 면에 안정적으로 놓인 주사위는 절대 보정하지 않는다.
4. 결과값을 바꾸지 않는다. 물리 자세를 결과값에 맞는 안정 자세로 보정한다.
5. D6/D8을 공통 인터페이스로 처리하되 각 도형의 면 법선과 지지 높이를 사용한다.
6. 호스트가 보정 결과를 확정하고 관전자에는 최종 변환만 전달해 멀티플레이 결과를 일치시킨다.

## 4. 구현 설계

### 4.1 안정성 판정기 분리

`src/DiceSettleStabilizer.js`를 추가한다.

- 입력: Cannon body, 주사위 설정(D6/D8), 바닥 Y, 현재 선형/각속도
- 출력: `stable`, `needsCorrection`, `supportFace`, `targetQuaternion`
- 책임: 자세 판정과 보정 목표 계산만 담당한다. 물리 월드·UI·네트워크를 직접 제어하지 않는다.

판정 기준은 다음 값을 상수화해 초기 튜닝한다.

| 항목 | 초기 기준 | 의미 |
|---|---:|---|
| 선형 속도 | `<= 0.45` | 아직 크게 미끄러지는 경우 제외 |
| 각속도 | `<= 0.8` | 회전 중인 경우 제외 |
| 면 정렬 기준 | `upDot >= 0.92` | 가장 위 면이 수직에 충분히 가까운지 |
| 보정 대기 | `0.12초` | 임계값 통과 직후의 순간 상태 제외 |

`upDot`은 도형별 모든 면 법선을 현재 quaternion으로 월드 좌표로 변환한 뒤, 월드 위쪽 `(0, 1, 0)`과의 내적 최대값으로 계산한다. 최대값이 기준 미만이면 모서리/꼭짓점 상태로 간주한다.

### 4.2 보정 목표 계산

- D6: 현재 위쪽에 가장 가까운 유효 면을 선택하고, 해당 면의 법선이 월드 위쪽을 향하는 quaternion을 생성한다.
- D8: 기존 물리 면 인덱스와 동일한 8개 삼각면 법선 표를 사용해 목표 quaternion을 생성한다.
- 주사위의 현재 결과값이 이미 정해진 경우에는 값에 대응하는 면을 우선한다. 결과값이 아직 없으면 가장 가까운 유효 면을 사용한다.
- 목표 위치 Y는 `playSurfaceY + supportHeight + clearance`로 재계산해 바닥 관통을 방지한다. X/Z는 현재 위치를 유지한다.

### 4.3 보정 연출과 종료 순서

`DiceEngine`의 종료 처리에 다음 단계를 삽입한다.

`ROLLING → SETTLING 판정 → (필요 시) STABILIZING → 결과 확정 → ARRANGED`

1. 각 주사위가 저속 상태인지 확인한다.
2. 모서리/꼭짓점 상태라면 body를 월드에서 분리하거나 kinematic 상태로 전환한다.
3. `0.12~0.18초` 동안 현재 quaternion을 목표 quaternion으로 slerp한다.
4. 같은 시간 동안 Y만 안전 높이로 보정하고 X/Z 이동은 최소화한다.
5. 보정 완료 후 기존 결과값 계산·정렬·클릭 활성화 흐름을 수행한다.

보정 중에는 사운드와 새로운 충돌 이벤트를 발생시키지 않는다. 짧고 낮은 진폭의 착지 효과음은 별도 UX 검토 후 선택적으로 추가한다.

### 4.4 강제 종료와 멀티플레이

- 2.5초 강제 종료 직전에도 안정성 판정을 1회 수행한다.
- 호스트는 보정 후 `finalTransforms`와 최종 값을 전송한다.
- 관전자는 로컬에서 보정 판정을 다시 실행하지 않고 수신한 최종 변환을 사용한다. 네트워크 지연으로 인한 결과 불일치를 막는다.
- `forceRollEnd()` 및 테이블 뒤집기 경로는 보정 상태를 정리하고 기존 종료 흐름으로 복귀해야 한다.

## 6. 검증 계획

1. D6, 무거운 D6, D8을 각각 100회 이상 자동 투척한다.
2. 일반 5개, 혼합 6개, 단일 D8 구성에서 모서리/꼭짓점 최종 자세가 0건인지 확인한다.
3. 이미 면으로 안정된 주사위가 불필요하게 튀거나 값이 바뀌지 않는지 확인한다.
4. 중앙 낙하, 6시 방향 진입, 보드 경계 복구가 기존과 동일하게 동작하는지 회귀 검증한다.
5. 호스트/관전자 동시 테스트에서 최종 값과 quaternion이 일치하는지 확인한다.
6. `npm run build` 및 브라우저 콘솔 오류 0건을 확인한다.

## 7. 완료 기준

- 굴림 종료 화면에서 D6/D8이 모서리·꼭짓점으로 서 있는 상태가 남지 않는다.
- 보정은 저속 종료 구간에서만 보이며, 투척의 물리적인 인상을 훼손하지 않는다.
- 주사위 값, 점수, 보관, 멀티플레이 최종 결과에 회귀가 없다.

## 8. 현재 결정

- 종료 직전의 별도 보정은 결과가 확정되기 전에 주사위가 회전하는 문제를 만들었다.
- 별도 안정화 회전은 제거하고, 결과 확정 뒤 실행되는 기존 `arrangeAll(true)` 정렬 단계만 회전·정리를 담당한다.
- 향후 별도 안정화가 필요하면, 결과 확정 이벤트 뒤에만 연결해야 한다.
