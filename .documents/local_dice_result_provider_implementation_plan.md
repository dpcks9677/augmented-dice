# 로컬 주사위 결과 공급 계층·프리셋 전환 구현계획서

## 구현 상태

- 완료: 증강 충돌 공통 규칙과 서버 최종 선택 검증
- 완료: 공통 주사위 눈금 규칙과 로컬 결과 공급자
- 완료: 공통 프리셋 키·프레임 슬롯 유효성 검사
- 완료: 연습·핫시트·로컬 증강모드의 프리셋 굴림 연결
- 완료: 정확한 프리셋 누락 시 기존 물리 굴림 fallback
- 완료: 화면 전환·새 게임 시 진행 중 로컬 결과 무효화 토큰
- 검증 필요: 로그인 후 실제 연습·핫시트 WebGL 굴림 수동 확인

## 1. 목적

핫시트·연습·로컬 게임의 주사위 결과 결정과 화면 애니메이션을 분리함. 로컬 규칙이 결과를 먼저 확정하고, 같은 결과를 프리셋 애니메이터 또는 기존 물리 엔진에 전달할 수 있게 함.

- 런타임에서 프리셋을 새로 베이크하지 않음.
- 저장된 프리셋 JSON만 재생함.
- 점수·증강·킵 규칙은 애니메이션 구현에 의존하지 않게 함.
- 온라인은 기존 서버 권위 결과 공급을 유지함.
- 로컬은 새 로컬 결과 공급자를 사용함.
- 정확한 프리셋이 없을 때만 기존 물리 굴림으로 fallback함.

## 2. 현재 결합 문제

현재 로컬 굴림은 `gameRuntime.js`와 `DiceEngine.roll()`에 다음 책임이 섞여 있음.

1. 현재 증강으로 굴릴 주사위 종류와 개수를 구성함.
2. 킵 주사위를 제외함.
3. Cannon 물리 바디를 생성하고 굴림을 실행함.
4. 물리 정지 후 주사위 값을 판정함.
5. `activeDice`, `keptDice`, 남은 굴림 수, 로그를 갱신함.
6. 점수 미리보기와 정렬 애니메이션을 실행함.

프리셋 애니메이션은 재생 전에 최종값이 필요하지만, 기존 로컬 경로는 물리 정지 후 최종값을 얻음. 따라서 `DiceEngine.roll()`만 프리셋 재생으로 교체하면 규칙 상태와 화면 결과가 달라질 수 있음.

## 3. 목표 구조

```text
게임 입력
  -> RollRequest 생성
  -> 결과 공급자 선택
       온라인: 서버 권위 상태
       로컬: LocalDiceResultProvider
  -> RollOutcome 확정
  -> 애니메이션 실행기 선택
       정확한 프리셋 있음: Preset animator
       정확한 프리셋 없음: Physics fallback
  -> 애니메이션 완료
  -> RollOutcome 한 번만 게임 상태에 반영
```

결과 생성과 연출을 분리하되, 기존 `DiceEngine`의 메시·재질·정렬·킵 존 기능은 그대로 재사용함.

## 4. 데이터 계약

### RollRequest

- `action`: `roll` 또는 `tableFlip`
- `player`: 현재 플레이어
- `configs`: 이번에 새로 굴릴 주사위 설정 배열
- `keptDice`: 유지할 주사위 ID·종류·값
- `rollIndex`: 현재 턴의 굴림 순서
- `augmentState`: 프로모션 레벨 등 결과 생성에 필요한 최소 상태

### RollOutcome

- `dice`: 전체 주사위의 ID·종류·값·킵 상태
- `rolledDice`: 이번에 애니메이션할 주사위만 포함함.
- `presetKey`: `normal_5`, `normal_6`, `mixed_3normal_2octa` 등의 정확한 키
- `presetIndex`: 선택한 프리셋 번호
- `mirrored`: 좌우 반전 여부
- `animationDuration`: 입력 잠금과 완료 처리에 사용할 시간
- `source`: `server`, `local-preset`, `local-physics`

`RollOutcome`은 애니메이션과 게임 상태 반영이 함께 참조하는 단일 결과여야 함. 애니메이션 종료 후 주사위 값을 다시 계산하지 않음.

## 5. 로컬 결과 공급자

### 책임

- 주사위 설정별 가능한 눈금에서 결과를 선택함.
- 일반·무거운·황금·8면·이상한·프로모션·커플·세븐 주사위를 처리함.
- 기존 킵 주사위는 값과 ID를 유지함.
- 새로 굴리는 주사위에만 새 ID와 결과를 부여함.
- 테스트에서 난수 함수를 주입할 수 있게 함.

### 비책임

- 메시 생성
- Cannon 물리 실행
- 점수 계산
- 로그 출력
- 프리셋 프레임 보간

온라인 `authoritativeGame.js`와 동일한 눈금 정의를 재사용해야 함. `DIE_FACES`를 별도 순수 규칙 모듈로 옮기거나 export해 서버·로컬 결과 공급자가 같은 표를 참조하게 함.

## 6. 프리셋 선택 규칙

- 8면체가 없으면 `normal_{굴리는 개수}`를 사용함.
- 8면체가 있으면 `mixed_{6면계열 수}normal_{8면체 수}octa`를 사용함.
- 판 뒤집기는 `flip_{전체 개수}`를 사용함.
- 킵 재굴림은 전체 주사위 수가 아니라 이번에 새로 굴리는 주사위 수로 프리셋을 선택함.
- 무거운·황금·이상한·프로모션·커플·세븐 주사위는 충돌 형태가 6면체이므로 프리셋 키 계산에서는 6면계열로 취급함.
- 프리셋 데이터의 각 슬롯은 `configs` 순서와 정확히 일치해야 함.

## 7. 프리셋 fallback 원칙

정확한 키가 없을 때 다른 개수의 프리셋을 대신 사용하지 않음. 예를 들어 6개 굴림을 `normal_5`로 재생하면 6번째 프레임 슬롯이 없어 오류가 발생함.

1. 정확한 프리셋 키와 유효한 프레임 수를 확인함.
2. 프리셋이 있으면 목표값 기반 프리셋을 재생함.
3. 없으면 기존 `DiceEngine.roll()` 물리 경로를 실행함.
4. fallback 결과는 물리 종료 후 `RollOutcome` 형식으로 정규화함.
5. fallback 발생 이유와 키를 개발 로그에 한 번 기록함.

## 8. 상태 반영 시점

- 굴림 시작 시 `pendingRollOutcome`을 저장함.
- 애니메이션 중 굴림·킵·점수 버튼을 잠금함.
- 애니메이션 완료 후 `pendingRollOutcome`과 현재 굴림 토큰이 일치할 때만 상태를 반영함.
- 취소·화면 전환·새 게임 시작 시 기존 토큰을 무효화함.
- `activeDice`, `keptDice`, 로그, 점수 미리보기는 하나의 완료 함수에서 갱신함.
- 물리 fallback과 프리셋 성공 경로가 같은 완료 함수를 사용하게 함.

이 구조로 프리셋 완료와 물리 완료가 중복 반영되는 문제를 방지함.

## 9. 이상한 주사위·8면 주사위 상호 배제

### 규칙

- `strange-die`를 보유한 플레이어에게 `8-sided`를 제시하지 않음.
- `8-sided`를 보유한 플레이어에게 `strange-die`를 제시하지 않음.
- 이미 두 증강을 동시에 가진 과거 상태를 불러오면 새 획득은 막되 저장 데이터를 자동 삭제하지 않음.
- 현재 `strange-die`의 `isAvailable: false`와 서버 `UNAVAILABLE_AUGMENTS`는 유지함. 추후 활성화할 때 상호 배제 검증을 먼저 적용함.

### 구현 위치

내부 규칙은 `src/augments.json`에 넣지 않음. 이 파일은 UI용 데이터만 유지함.

`src/augmentRules.js`에 순수 규칙을 둠.

- `AUGMENT_CONFLICTS`: 양방향 충돌 관계
- `hasAugmentConflict(ownedIds, candidateId)`
- `canAcquireAugment(ownedIds, candidateId)`

적용 지점:

1. `authoritativeGame.js#getDraftOptions`: 온라인 후보 생성 전 필터링
2. `authoritativeGame.js#selectAugment`: 조작된 명령에 대한 최종 검증
3. `gameRuntime.js#getSeededAugments`: 핫시트·로컬 후보 생성 전 필터링
4. 디버그·개발자 강제 적용 기능: 동일 검증 또는 명시적 우회 옵션 사용

기존 `table-flip` ↔ `8-sided` 상호 배제도 같은 규칙 표로 이동해 중복 조건을 제거함.

## 10. 구현 단계

### 1단계: 규칙과 결과 타입 고정 — 완료

- `DIE_FACES` 공유 위치를 확정함.
- `RollRequest`, `RollOutcome`의 JSDoc 타입을 작성함.
- 현재 일반·특수 주사위 결과를 특성 테스트로 고정함.
- 증강 충돌 순수 함수와 테스트를 추가함.

### 2단계: 증강 상호 배제 선조치 — 완료

- 온라인·로컬 드래프트 후보 필터를 공통 규칙으로 교체함.
- `selectAugment`에서 충돌 증강 선택을 오류로 거부함.
- 양방향 순서와 자동 선택을 테스트함.
- `strange-die`는 계속 비활성 상태로 둠.

### 3단계: LocalDiceResultProvider 추가 — 완료

- 현재 `gameRuntime.js`의 주사위 설정 생성 결과를 입력으로 받음.
- 주사위별 값을 결정하고 `RollOutcome`을 반환함.
- 킵·재굴림·프로모션 레벨·6개 구성을 단위 테스트함.

### 4단계: 공통 프리셋 선택기 추출 — 완료

- 서버의 프리셋 파일명 계산과 `DiceEngine`의 캐시 키 계산을 하나의 순수 함수로 통일함.
- 정확한 키 존재·주사위 수·프레임 슬롯 수를 검증함.
- `normal_1~6`, 혼합 1~5, 뒤집기 1~6을 테스트함.

### 5단계: 로컬 일반모드 전환 — 코드 완료, 수동 검증 필요

- 증강이 없는 연습·일반 핫시트부터 프리셋 경로를 적용함.
- 첫 굴림과 킵 후 1~4개 재굴림을 검증함.
- 입력 잠금·로그·점수 미리보기·정렬을 검증함.

### 6단계: 로컬 증강모드 전환 — 코드 완료, 수동 검증 필요

- 특수 6면계열 주사위를 연결함.
- 8면체 혼합 프리셋을 연결함.
- 이상한 주사위 6개 구성은 `normal_6`을 사용함.
- 프로모션 소모·이상한 주사위 파괴·특수 점수 보너스를 검증함.

### 7단계: fallback·복구 검증 — 자동 검증 완료, 수동 검증 필요

- 프리셋 누락·손상·프레임 수 불일치 시 물리 fallback을 확인함.
- 화면 전환과 새 게임으로 진행 중 굴림이 취소되는지 확인함.
- fallback 이후 다음 굴림이 정상 프리셋 경로로 복귀하는지 확인함.

### 8단계: 레거시 중복 정리

- 프리셋·물리 경로에 중복된 완료 후 상태 반영 코드를 제거함.
- 결과 판정이 더 이상 필요 없는 물리 전용 함수는 사용처 확인 후 정리함.
- 디버그 도구와 프리셋 스튜디오의 공통 키 계산을 재사용함.

## 11. 예상 변경 파일

- `src/diceRules.js` 또는 기존 순수 규칙 파일: 눈금 정의와 결과 생성 보조 함수
- `src/localDiceResultProvider.js`: 로컬 결과 공급자
- `src/dicePresetRules.js`: 공통 프리셋 키·유효성 계산
- `src/augmentRules.js`: 증강 충돌 규칙
- `src/gameRuntime.js`: 요청 생성, 결과 공급자 호출, 단일 완료 처리
- `src/DiceEngine.js`: 프리셋 재생·물리 fallback 실행 계약 정리
- `src/server.js`: 공통 프리셋 키 계산 사용
- `src/authoritativeGame.js`: 공유 눈금·증강 충돌 규칙 사용
- 관련 단위·통합 테스트

새 파일은 역할이 실제로 분리되는 경우에만 추가함. 기존 파일의 순수 함수 export만으로 충분하면 별도 모듈 수를 줄임.

## 12. 검증 행렬

| 구분 | 필수 시나리오 |
| --- | --- |
| 일반 로컬 | 첫 굴림 5개, 킵 후 1~4개, 굴림 횟수 소진 |
| 일반 핫시트 | 플레이어 전환, 같은 프리셋 결과 공유 없음, 각 로컬 상태 유지 |
| 증강 로컬 | 특수 6면체, 8면체 1~2개 혼합, 프로모션, 이상한 주사위 6개 |
| 상호 배제 | 이상한→8면 차단, 8면→이상한 차단, 자동 선택 차단, 조작 명령 차단 |
| fallback | 파일 없음, JSON 손상, 슬롯 수 불일치, 재생 중 오류 |
| 회귀 | 온라인 매치메이킹·로비 권위 굴림, 점수, 킵, 재접속 |

## 13. 완료 조건

- 로컬 규칙이 애니메이션 실행 전에 주사위 결과를 확정함.
- 프리셋과 물리 fallback이 동일한 `RollOutcome` 완료 경로를 사용함.
- 모든 로컬 모드에서 프리셋 성공 시 Cannon 굴림 결과를 다시 계산하지 않음.
- 프리셋이 없으면 게임이 멈추지 않고 기존 물리 굴림으로 복구함.
- `strange-die`와 `8-sided`가 어떤 획득 순서에서도 동시에 제시·선택되지 않음.
- 온라인 권위 굴림과 레이팅·로비 입장 구조에 회귀가 없음.

## 14. 권장 작업 순서

1. 증강 충돌 규칙과 테스트
2. 결과 계약과 로컬 결과 공급자 테스트
3. 공통 프리셋 키 계산기
4. 일반 연습모드 적용
5. 일반 핫시트 적용
6. 증강 로컬모드 적용
7. 물리 fallback과 취소 처리
8. 온라인 회귀 테스트와 중복 정리

상호 배제 선조치를 먼저 완료하면 6개 이상한 주사위와 8면체가 섞인 프리셋 조합을 지원하지 않아도 됨. 단, 저장 데이터나 디버그 강제 적용으로 충돌 상태가 들어오는 경우를 고려해 런타임은 오류 없이 물리 fallback할 수 있어야 함.
