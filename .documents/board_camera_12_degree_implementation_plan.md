# 보드 카메라 12도 개선 구현계획서

## 확인 결과

- 현재 보드 카메라 기본 각도는 `setCameraAngle()`의 0도임.
- 카메라 각도 변경 시 카메라 `y`가 바뀌며, `getViewHeight()`가 이를 사용해 트레이 스케일이 간접적으로 바뀔 수 있음.
- 주사위와 동전 위치는 `tray.getLayout(getViewHeight())`에서 계산되므로 플레이 표면 높이와 배치 기준도 함께 달라질 수 있음.
- `PresetBaker`는 고정 `viewHeight`를 사용하므로 베이킹 물리 좌표 자체는 카메라 각도에 직접 영향받지 않음.

## 목표

- 보드 모드 초기 카메라 각도를 12도로 변경함.
- 각도 조절은 시점만 변경하고 보드·주사위·동전의 월드 좌표와 크기는 유지함.
- 보드 전체가 화면에 들어오도록 카메라 프레이밍과 트레이 스케일을 분리함.

## 구현 방법

1. 보드 기본 각도 12도와 보드 기준 뷰 높이를 상수로 정의함.
2. 보드 진입·창 크기 변경 시에만 기준 뷰 높이로 트레이를 `resize()`하고, 각도 입력에서는 `resize()`하지 않도록 분리함.
3. `setCameraAngle()`은 카메라 위치와 `OrbitControls.target`만 갱신함.
4. 콘텐츠 배치는 보드 기준 레이아웃을 재사용해 각도 변경 중 `playSurfaceY`와 x/z 위치가 변하지 않도록 함.
5. 12도에서 트레이 외곽, 플레이 영역, 주사위, 동전의 클리핑 여부를 확인하고 필요 시 FOV 또는 카메라 거리만 조정함.
6. 슬라이더 기본값, 초기화 버튼, 각도 표시값을 12도로 동기화함.

## 검증 계획

- 0도·12도·75도에서 트레이와 콘텐츠 월드 좌표가 유지되는지 확인함.
- 단일·복수·혼합 주사위와 복수 동전의 위치·바닥 접촉·클리핑을 확인함.
- 창 크기 변경 후에도 보드가 화면에 맞는지 확인함.
- `npm run build`, `npm run test:main-structure`, `node tests/coinModel.test.mjs`, `git diff --check` 실행함.

## 변경 예정 파일

- `src/presetStudio.js`: 보드 카메라 기본값과 기준 레이아웃 분리
- `preset-studio.html`: 슬라이더 기본값 및 표시값 동기화
- 본 계획서: 구현 결과와 검증 기록 추가

## 구현 결정 추가

- 윗면만 보이게 하는 요구사항에 따라 보드 모드 주사위에 카메라 각도와 동일한 X축 보정 회전을 적용함.
- 베이킹 프레임의 원래 quaternion을 먼저 보간한 뒤 보정 quaternion을 합성해 애니메이션 회전과 카메라 보정을 분리함.
- 모델 뷰어 모드와 동전에는 주사위 보정 회전을 적용하지 않음.

## 정렬 애니메이션 회전 적용 방식

- 굴림 중에는 기존 베이킹 프레임의 위치·quaternion을 그대로 사용함.
- 굴림이 끝난 뒤 주사위 정렬 애니메이션을 시작하고, 이 정렬 구간에서 위치 이동과 12도 회전 보정을 동시에 적용함.
- 정렬 위치는 기존 보드 좌표 기준을 유지하며, 회전 보정은 시각 연출용 공통 X축 quaternion으로 별도 관리함.
- 정렬 완료 후에는 보정된 최종 quaternion을 유지하고, 매 프레임 베이킹 quaternion에 보정값을 반복 적용하지 않음.
- 정렬 대상이 아닌 일반 시뮬레이션 주사위와 모델 뷰어 주사위에는 이 정렬 보정을 적용하지 않음.

### 구현 순서

1. 굴림 재생 종료 시 최종 주사위 상태를 캡처함.
2. 각 주사위의 정렬 목표 X/Z 좌표와 12도 보정 quaternion을 계산함.
3. 정렬 진행률에 따라 위치를 easing하고, 기존 최종 quaternion에서 보정 quaternion까지 회전 보간함.
4. 정렬 종료 시 최종 위치와 보정된 quaternion을 고정함.

## 게임 모드 영향 점검

- 연습 모드: `gameRuntime.js`의 mode-select 롤 경로가 `diceEngine.roll()` 후 `arrangeAll(true)`를 호출하므로, 정렬 애니메이션 보정은 클라이언트 `DiceEngine` 단계에서 적용 가능함.
- 핫시트/로컬 게임: 일반 롤 경로도 동일하게 `diceEngine.roll()`과 `arrangeAll()`을 사용하므로, 플레이어 전환과 주사위 결과 계산에는 영향이 없어야 함.
- 온라인 권위 모드: 서버가 보내는 주사위 결과·spawn transform·상태 계약은 변경하지 않고, 클라이언트 표시 단계의 정렬 보정만 적용해야 함. 서버 파일과 authoritative state는 수정하지 않음.
- 점수 계산과 유지 주사위 판정은 기존 quaternion/결과값이 아니라 DiceEngine의 결과 상태를 사용하므로, 시각 보정 회전은 판정 로직과 분리해야 함.

### 모드별 검증 항목

1. 연습 모드에서 첫 롤과 재롤 후 정렬 이동·회전이 완료되고 버튼이 다시 활성화되는지 확인함.
2. 핫시트에서 P1/P2 턴 전환, 유지 주사위, 재롤 후 정렬이 정상인지 확인함.
3. 로컬 게임에서 일반·증강 게임의 정렬 보정과 점수 계산 결과가 기존과 동일한지 확인함.
4. 온라인 권위 모드에서는 이번 클라이언트 전용 변경이 서버 payload·상태 revision·주사위 결과를 변경하지 않는지 확인함.
