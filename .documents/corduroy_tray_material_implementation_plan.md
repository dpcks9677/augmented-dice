# 게임보드 버건디 영역 코듀로이 재질 적용 계획서

## 1. 목표

`yacht-tray.stl`의 버건디 플레이·킵 영역에 붉은 코듀로이 패브릭 질감을 적용함.

- STL 형상과 주사위 충돌 판정은 유지함.
- 버건디 바닥과 버건디 측면 벽 영역 모두 코듀로이 재질로 표시함.
- 바닥과 벽면의 코듀로이 패턴은 서로 연결하지 않고 각각 독립적으로 표시함.
- 테두리·램프·기타 STL 영역은 기존 재질을 유지함.
- 온라인·연습·핫시트·로컬 모드의 게임 로직에는 영향을 주지 않음.

## 2. 현재 구조

- `src/YachtTrayModel.js`에서 STL을 단일 메시로 로드함.
- `applyVertexColors()`가 위치 기준으로 플레이 영역·킵 영역·테두리를 vertex color로 구분함.
- 단일 `MeshStandardMaterial`에 `vertexColors: true`를 사용함.
- STL에는 UV 좌표가 없으므로 텍스처 파일을 즉시 매핑할 수 없음.
- 물리 충돌은 `getCollisionProfile()`의 별도 프로파일을 사용함.

## 3. 사용할 에셋

### 필수

- `Fabric026_2K-PNG_Color.png`: 코듀로이 기본 색상
- `Fabric026_2K-PNG_NormalGL.png`: 섬유 골·줄무늬 입체감

### 권장

- `Fabric026_2K-PNG_Roughness.png`: 섬유 반사도 제어

### 선택

- `Fabric026_2K-PNG_Displacement.png`: 실제 높낮이 대신 범프 효과로 우선 사용함.

`NormalDX.png`, `.mtlx`, `.usdc`, 저해상도 `Fabric026.png`은 현재 Three.js 경로에서 사용하지 않음.

## 4. 권장 구현 방식

### 4.1 메시 분리

기존 STL의 vertex color 분류 기준을 재사용해 버건디 바닥·벽 영역과 외곽 영역을 분리함.

- 버건디 바닥: 바닥 전용 코듀로이 텍스처 재질
- 버건디 측면 벽: 벽면 전용 코듀로이 텍스처 재질
- 외곽 영역: 기존 `MeshStandardMaterial`
- 동일 위치에 두 메시가 겹치지 않도록 원본 geometry의 삼각형을 영역별로 재구성함.

단일 메시를 유지해야 하는 경우에는 vertex color 마스크를 셰이더에서 사용해 코듀로이 맵을 선택함. 초기 구현은 메시 분리보다 셰이더 마스크 방식을 우선 검토함.

### 4.2 UV 생성

STL에 UV가 없으므로 버건디 표면에 평면 투영 UV를 생성함.

- 수평 바닥: XZ 평면 기준 UV를 별도로 생성함.
- 측면 벽: 벽 방향에 맞는 XY 또는 ZY 평면 기준 UV를 별도로 생성함.
- 바닥 UV와 벽면 UV는 연결하지 않고 각각 원점부터 패턴을 시작함.
- 코듀로이 줄 방향과 반복 배율은 바닥·벽면별로 독립 조정함.
- 킵존 바닥과 플레이존 바닥도 필요 시 별도 UV 스케일을 사용함.

### 4.3 재질 설정

`MeshStandardMaterial` 기준으로 적용함.

- `map`: Color PNG
- `normalMap`: NormalGL PNG
- `roughnessMap`: Roughness PNG
- `roughness`: 기본값은 0.8~0.95 범위에서 조정
- `metalness`: 0 유지
- `normalScale`: 섬유 골이 과장되지 않도록 낮은 값부터 조정

색상·노멀·러프니스 텍스처는 Three.js 색상 공간 규칙에 맞춰 처리함. Color만 sRGB로 지정하고 Normal/Roughness는 선형 데이터로 유지함.

## 5. 파일·코드 변경 계획

### 에셋

- `public/textures/tray/corduroy-color.png`
- `public/textures/tray/corduroy-normal-gl.png`
- `public/textures/tray/corduroy-roughness.png`

원본 다운로드 폴더는 프로젝트 외부에 있으므로 필요한 파일만 복사함. 2K 텍스처 3장은 초기 적용에 필요한 최소 세트임.

### 코드

- `src/YachtTrayModel.js`
  - 코듀로이 텍스처 로딩
  - 버건디 바닥·벽 영역 마스크와 면별 UV 생성
  - 재질 생성 및 텍스처 dispose 처리
  - 로드 실패 시 기존 vertex color 재질로 폴백
- 필요 시 `src/DiceEngine.js`
  - 변경하지 않는 것을 원칙으로 하며, 재질 로딩 상태만 기존 트레이 로딩 콜백으로 처리함.

## 6. 구현 단계

1. 프로젝트 텍스처 디렉터리 생성 및 필수 3개 맵 복사함.
2. 현재 STL vertex color 영역 판정 기준을 별도 함수로 추출함.
3. 버건디 바닥과 벽면에 서로 독립적인 평면 UV를 생성함.
4. Color·NormalGL·Roughness 텍스처를 로드함.
5. 버건디 영역에 코듀로이 재질을 적용함.
6. 외곽·테두리 재질은 기존 vertex color 재질로 유지함.
7. 텍스처 로딩 실패·WebGL 미지원 시 기존 재질로 폴백함.
8. 줄 방향·반복 배율·normalScale·roughness를 조정함.
9. 게임 모드와 보드 크기별 회귀 검증을 수행함.

## 7. 주요 위험과 대응

### 텍스처 방향 왜곡

STL 표면의 좌표 방향과 텍스처 줄 방향이 어긋날 수 있음.

- 바닥·벽면별 UV 회전·반복 파라미터를 상수화함.
- 프리셋 스튜디오와 실제 게임 화면에서 방향을 비교함.

### 영역 경계 누출

버건디 마스크 경계에서 코듀로이 색상이 테두리로 번질 수 있음.

- 기존 vertex color 분류 기준을 그대로 사용함.
- 경계 삼각형에 대한 여유값을 별도 상수로 둠.

### 성능 부담

2K 텍스처 3장은 메모리 사용량과 모바일 GPU 비용을 증가시킬 수 있음.

- 기본은 2K 유지하되 모바일에서 1K로 낮출 수 있는 설정을 둠.
- 텍스처 반복과 normalScale을 과도하게 높이지 않음.
- 동일 텍스처를 여러 재질이 공유하도록 함.

### STL 표면과 UV 투영 불일치

바닥과 벽면을 하나의 UV로 투영하면 코듀로이가 늘어나거나 겹칠 수 있음.

- 바닥·벽면을 각각 독립적인 평면 UV 대상으로 분리함.
- 비버건디 측면·램프와 테두리는 기존 재질로 유지함.

## 8. 검증 계획

### 시각 검증

- 플레이·킵 바닥과 버건디 측면 벽 모두 붉은 코듀로이 줄무늬가 표시되는지 확인함.
- 바닥과 벽면의 패턴이 서로 연결되지 않고 각각 일정한 크기로 표시되는지 확인함.
- 벽면 패턴이 세로·가로 방향으로 늘어나지 않는지 확인함.
- 줄 방향이 각 면의 보드 축과 일치하는지 확인함.
- 주사위·그림자·호버 테두리가 패브릭 위에서 정상 표시되는지 확인함.
- 카메라 0도·12도 및 스튜디오 카메라 각도에서 확인함.

### 기능 검증

- 주사위 물리 충돌·투척·킵 위치가 변경되지 않는지 확인함.
- 온라인·연습·핫시트·로컬 게임에서 트레이 로딩을 확인함.
- 텍스처 요청 실패 시 기존 버건디 vertex color 재질로 복귀하는지 확인함.

### 자동 검증

- `npm run build`
- `git diff --check`
- 기존 주사위·서버 권위·프리셋 관련 테스트
- `graphify update .`

## 9. 완료 기준

- 버건디 바닥과 측면 벽에 코듀로이 패턴이 자연스럽게 표시됨.
- 바닥과 벽면 패턴은 연결되지 않지만 각 면 내부에서는 균일한 크기로 표시됨.
- 테두리와 기타 STL 영역의 기존 외관이 유지됨.
- 충돌 프로파일과 주사위 위치 계산이 변경되지 않음.
- 텍스처 로딩 실패 시 게임 진행이 중단되지 않음.
- 주요 게임 모드와 보드 카메라 각도 검증을 통과함.
