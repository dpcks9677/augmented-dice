# 6시 방향 주사위 투입 연출 및 보드 물리판 구현 계획서

- 작성일: 2026-07-28
- 상태: 구현 및 검증 완료
- 대상: `DiceEngine`, `YachtTrayModel`, 게임/로비 주사위 보드
- 이번 단계의 변경 범위: 계획과 인수인계 문서 작성만 수행하며 코드와 STL은 수정하지 않는다.

## 1. 목표

1. 굴리기 시작 시 주사위가 보드 내부에서 생성되지 않고, 화면 기준 6시 방향의 보드 바깥에서 중심을 향해 던져져 들어오는 연출을 만든다.
2. STL의 보이는 플레이면과 Cannon 물리면의 높이·경계를 일치시켜 주사위가 모델 안으로 파고들거나 보드 밖으로 빠지는 현상을 막는다.
3. 일반 D6, 무거운 주사위, 8면체 및 최대 6개 주사위 조합에서 같은 연출과 안정성을 보장한다.
4. 로컬과 멀티플레이에서 시작 궤적과 최종 결과 동기화 방식을 유지한다.
5. 점수 계산, 킵 규칙, 굴림 횟수 등 게임 규칙은 변경하지 않는다.

## 2. 현재 구현 조사 결과

### 2.1 투척 시작 위치

- `DiceEngine.roll()`은 현재 `playBounds.maxZ - 1` 부근, 즉 플레이 영역의 6시 방향 **안쪽**에서 주사위를 생성한다.
- 초기 Z 속도는 음수이므로 중심 방향으로 움직이지만, 바깥에서 들어오는 장면은 보이지 않는다.
- 6시 방향 경계에는 항상 정적 벽이 생성되어 있어, 시작 위치를 단순히 바깥쪽으로 옮기면 주사위가 벽에 막힌다.

### 2.2 현재 충돌 구조

- 바닥은 보드 크기와 무관한 `400 × 400` 크기의 대형 Cannon Box로 구성되어 있다.
- 네 벽과 천장은 STL 형상이 아니라 `playBounds`를 기준으로 만든 단순 Box 충돌체이다.
- 일반 굴림의 벽은 코드 주석의 높이보다 실제 Box 반높이가 더 크게 적용된다. 또한 천장이 투척 호를 가로막으므로 외부 투입 모드에서는 별도 경계 구성이 필요하다.
- STL 자체는 렌더링 전용이며 Cannon 충돌체로 사용되지 않는다. 이 방향은 유지하되, 단순 충돌 프록시를 STL 레이아웃에 정확히 결합한다.

### 2.3 모델과 주사위가 겹치는 원인

STL을 현재 코드와 같은 방식으로 변환해 측정한 결과는 다음과 같다.

- STL 원본 전체 범위: X `47.500…202.500`, Y `32.500…187.500`, Z `0…38.000`
- 변환 후 전체 범위: X/Z 약 `-77.5…77.5`, Y 약 `-14…24`
- 중앙 플레이면 측정 높이: 약 `Y=-10.284`
- 킵 포켓 중앙(`Z=-58`)의 표면 높이: 약 `Y=13`
- 현재 킵 포켓 배치 상수: `PLAY_SURFACE_Y=10`

즉, 플레이면은 실제 측정값을 일부 사용하지만 킵 포켓은 상수 `10`을 사용한다. 킵 주사위 바닥이 실제 포켓 표면보다 아래에 놓여 모델과 겹칠 수 있다. 레이아웃이 리사이즈될 때 이 오차도 같은 비율로 확대·축소된다.

### 2.4 로딩 및 동기화

- 주사위 엔진 생성 직후 `diceBoxReady=true`가 되어 STL 측정과 충돌판 준비가 끝나기 전에 굴림이 활성화될 수 있다.
- 멀티플레이는 호스트의 위치, 회전, 선속도, 각속도를 `spawnTransforms`로 전달하고 마지막 결과를 다시 보정한다. 외부 투입도 이 데이터 구조를 유지하면 기존 방식과 호환된다.

## 3. 채택할 구현 방식

### 3.1 STL은 렌더링 자산으로 유지

`public/models/yacht-tray.stl` 바이너리는 수정하지 않는다. STL 전체를 Cannon `Trimesh`로 변환하는 방식도 사용하지 않는다. 오목한 트레이의 삼각형 충돌은 비용이 크고 작은 모서리에서 튐·끼임을 만들 가능성이 높기 때문이다.

대신 `YachtTrayModel`이 측정한 표면과 경계를 기준으로 다음의 보이지 않는 단순 충돌 프록시를 결합한다.

- 플레이 영역용 평평한 바닥 Box
- 6시 방향 외부 투입 구간용 임시 평평한 진입판
- 평상시 네 방향 벽
- 투입 중 진입로 양옆 가이드 벽과 바깥쪽 안전벽
- 평상시 천장과 투입 중 개방된 천장 상태

### 3.2 단일 레이아웃 좌표 계약

`YachtTrayModel.getLayout()`이 렌더링과 물리 양쪽에서 사용할 다음 값을 제공하도록 확장한다.

- `playSurfaceY`: 중앙 플레이면을 레이캐스트로 측정한 높이
- `playBounds`: 실제 플레이 영역 X/Z 경계
- `outerBounds`: STL 외곽 경계
- `keepPoints[]`: 각 킵 포켓의 X/Y/Z 실측 좌표
- `entryEdgeZ`: 6시 방향 플레이 영역 진입선
- `launchOriginZ`: STL 외곽보다 바깥인 투척 시작선
- `activeCenterZ`: 투척 목표가 되는 플레이 영역 중심
- `scale`: 현재 뷰포트에 적용된 STL 배율

플레이면과 킵 포켓의 Y 값은 각각 실제 표면 측정값에서 계산하며, `PLAY_SURFACE_Y=10` 같은 서로 다른 수동 높이 상수는 제거하거나 실패 시 폴백으로만 제한한다.

### 3.3 물리판 구성

기존 무한대에 가까운 바닥 Box를 다음 두 판으로 분리한다.

1. **보드 물리판**
   - X/Z 크기는 `playBounds`와 주사위 반경 여유분으로 계산한다.
   - Box 윗면이 정확히 `playSurfaceY`가 되도록 `body.position.y = playSurfaceY - thickness / 2`로 둔다.
   - 충분한 두께를 사용해 빠른 낙하 시 터널링을 막는다.

2. **임시 진입판**
   - `entryEdgeZ`부터 `launchOriginZ` 바깥쪽까지 이어진다.
   - 보드 물리판과 윗면 높이를 동일하게 맞춘다.
   - 투입 단계에서만 활성화하고 모든 주사위가 보드 안으로 들어오면 제거한다.

진입판은 투척 실패 시 주사위가 아래로 사라지는 것을 막는 안전장치이며, 정상 궤적에서는 주사위가 보드 림을 공중으로 넘어 플레이판에 처음 충돌하도록 속도를 조정한다.

### 3.4 경계 상태

물리 경계를 두 상태로 관리한다.

- `NORMAL`
  - 플레이 영역의 네 벽과 낮은 천장을 사용한다.
  - 6시 방향 벽이 닫혀 있어 튕긴 주사위가 밖으로 나가지 않는다.

- `INGRESS`
  - 플레이 영역의 6시 방향 벽을 연다.
  - 진입판 바깥 끝에 안전벽을 두고, 좌우 벽을 진입판 끝까지 연장한다.
  - 보드 림을 넘는 포물선을 막지 않도록 평상시 천장을 비활성화하거나 충분히 높인다.
  - 모든 투척 대상 주사위 중심이 `entryEdgeZ - 안전 여유` 안쪽으로 들어온 뒤 6시 방향 벽을 다시 닫고 `NORMAL`로 전환한다.

경계 재구성은 `updateWalls(boolean)` 대신 의미가 드러나는 `configureBoundaries(mode, layout)` 형태로 분리한다. 리사이즈가 굴림 중 발생해도 현재 모드를 유지한다.

### 3.5 외부 투척 프로필

- 화면 좌표 기준 6시 방향은 월드 좌표 `+Z`로 정의한다.
- 시작점은 `launchOriginZ` 바깥에 두어 최초 프레임에는 캔버스 밖 또는 보드 외곽에 있다가 안으로 들어오게 한다.
- X 위치는 주사위 수에 따라 부채꼴로 분산하되, 서로의 충돌체가 시작 시 겹치지 않도록 최소 간격을 둔다.
- 목표점은 `activeCenterZ` 주변으로 분산한다.
- Y 위치와 초기 Y/Z 속도는 비행 시간과 목표점으로 계산하여, 보이는 STL 림 최고점에 주사위 지지 반경과 안전 여유를 더한 높이를 통과하게 한다.
- 회전 속도는 기존 무작위성을 유지하되 과도한 각속도로 물리 스텝이 불안정해지지 않도록 상한을 둔다.
- 일반, 무거운 주사위, 8면체는 동일한 궤적 생성 함수를 쓰고 질량·형상별 지지 반경만 다르게 제공한다.

트레이가 화면의 약 96%를 차지하므로 첫 장면은 화면 밖에서 나타나는 방식으로 먼저 구현한다. 연출이 충분히 읽히지 않을 때만 `TRAY_VIEW_FILL`을 소폭 낮춰 6시 방향 여백을 확보하며, 보드 크기 변경은 2차 조정으로 둔다.

### 3.6 굴림 상태 흐름

굴림 흐름을 다음 상태로 명확히 나눈다.

`IDLE → INGRESS → ROLLING → SETTLING → ARRANGED`

- `INGRESS`: 진입판/가이드 활성화, 주사위 외부 생성 및 림 통과
- `ROLLING`: 모든 주사위 진입 후 평상시 경계 복구
- `SETTLING`: 기존 sleep 판정과 결과 계산
- `ARRANGED`: 기존 중앙 정렬 및 킵 상호작용

오류, 강제 종료, 관전자 최종 보정 시에도 `finally` 성격의 정리 함수로 임시 진입판과 경계를 반드시 원복한다. 판 뒤집기 기능은 별도 경계 모드를 유지하되 새 상태 관리와 충돌하지 않게 한다.

### 3.7 모델 겹침 보정

- 플레이 중 주사위 중심 높이는 `playSurfaceY + shapeSupportHeight + clearance` 이상으로 보장한다.
- 킵 주사위는 각 `keepPoints[index].y`를 기준으로 배치한다.
- D6와 D8은 형상이 다르므로 단일 `DIE_HALF_SIZE` 대신 현재 회전에 대한 수직 지지 높이 또는 보수적인 형상별 지지 높이를 사용한다.
- 바닥과 주사위 사이의 시각적 여유는 매우 작은 `clearance` 하나로 통일한다.
- 정렬 그림자의 Y 값도 플레이면 또는 해당 킵 포켓 표면을 사용하도록 맞춘다.

### 3.8 로딩과 멀티플레이

- `DiceEngine`에 준비 완료 Promise 또는 `onReady`를 추가한다.
- STL 측정과 초기 충돌판 생성이 끝난 뒤에만 `diceBoxReady=true`로 전환한다.
- STL 로드 실패 시에는 명시적인 폴백 레이아웃으로 충돌판을 만들고 같은 준비 절차를 완료한다.
- 호스트는 기존처럼 투척 시작 변환값을 전송한다.
- 관전자도 `roll(..., true, spawnTransforms)` 진입 시 `INGRESS` 경계를 활성화한다.
- 최종 결과 수신 또는 타임아웃 시 임시 경계를 정리하고 기존 `forceRollEnd` 보정을 적용한다.

## 5. 구현 순서

1. **좌표 계약 정리**
   - STL 변환 이후 플레이면과 5개 킵 포켓을 측정한다.
   - 수동 높이 상수를 폴백으로 격리하고 렌더링/물리 공용 레이아웃을 만든다.

2. **충돌 프록시 재구성**
   - 대형 바닥을 보드 크기의 평평한 물리판으로 교체한다.
   - 평상시 벽/천장을 레이아웃 기준으로 다시 만든다.
   - 디버그 표시로 STL 표면과 충돌판의 높이 및 경계를 확인한다.

3. **외부 진입 상태 구현**
   - 임시 진입판, 연장 가이드, 바깥 안전벽, 열린 천장을 만든다.
   - 모든 대상 주사위의 진입 완료를 감지하고 평상시 경계를 복구한다.

4. **투척 궤적 구현**
   - 6시 방향 외부 시작점과 중심 목표점을 계산한다.
   - 개수/형상별 간격, 속도, 회전량을 조정한다.
   - 최대 굴림 시간 안에 자연스럽게 안착하도록 감쇠와 초기 속도를 튜닝한다.

5. **겹침 및 준비 상태 수정**
   - 플레이면과 킵 포켓의 주사위 높이를 실측 Y 기준으로 교체한다.
   - STL과 물리판 준비 전 굴림을 차단한다.

6. **멀티플레이·예외 경로 연결**
   - 호스트/관전자 모두 같은 경계 상태를 사용하게 한다.
   - 강제 종료, 타임아웃, 리사이즈, 판 뒤집기 이후 임시 충돌체가 남지 않는지 확인한다.

7. **검증 및 기록**
   - 아래 검증 매트릭스를 통과한 뒤 버그 로그와 인수인계를 갱신한다.

## 6. 검증 계획

### 6.1 기능 검증

- 첫 굴림과 리롤 모두 주사위가 6시 방향 외부에서 들어온다.
- 킵된 주사위는 유지되고, 굴릴 대상만 외부에서 재진입한다.
- 1개, 5개, 6개 투척에서 시작 충돌이나 겹침이 없다.
- 일반 D6, 무거운 D6, D8 및 혼합 조합이 보드 림을 통과한다.
- 진입 후 6시 방향 경계가 닫혀 주사위가 다시 밖으로 빠지지 않는다.
- 굴림 종료, 강제 종료, 판 뒤집기, 화면 리사이즈 뒤 임시 진입판과 경계가 남지 않는다.

### 6.2 물리 안정성 검증

- 기본 크기와 최소/최대 지원 화면 크기에서 각 대표 조합을 100회 반복한다.
- 다음 조건을 자동 또는 디버그 계측으로 확인한다.
  - 보드 밖 이탈 0회
  - 바닥 아래 추락 0회
  - 정지 후 STL 표면 침투 허용치 이하
  - 최대 굴림 대기 시간을 넘긴 강제 종료 비율이 허용치 이하
  - 모든 동적 Body와 임시 정적 Body가 종료 후 정상 정리됨

### 6.3 시각 검증

- 주사위가 화면 아래에서 나타나 보드 중심을 향하는 방향성이 한눈에 읽힌다.
- 보드 림을 통과할 때 림을 뚫지 않고 위로 넘어온다.
- 플레이면과 킵 포켓에서 주사위 밑면이 모델 안으로 파고들지 않는다.
- 주사위 그림자와 실제 접촉면의 위치가 일치한다.
- 외부 투입을 위해 보드가 지나치게 작아지거나 기존 점수판 레이아웃이 흔들리지 않는다.

### 6.4 멀티플레이 검증

- 호스트와 게스트에서 투척 방향과 최소 연출 시간이 일치한다.
- 지연된 `sync_roll_end`가 도착해도 진입판과 열린 경계가 남지 않는다.
- 최종 눈과 최종 변환은 기존 호스트 권위 보정 결과와 동일하다.

## 7. 완료 기준

다음 조건을 모두 만족하면 구현 완료로 판단한다.

1. 주사위가 6시 방향의 보드 외부에서 중심으로 투입되는 장면이 매 굴림에서 재현된다.
2. 대표 조합 반복 시험에서 이탈·추락이 발생하지 않는다.
3. 플레이면 및 5개 킵 포켓에서 모델과 주사위의 눈에 띄는 겹침이 없다.
4. 굴림 완료 시간과 조작 잠금 시간이 기존 게임 흐름을 방해하지 않는다.
5. 로컬과 멀티플레이의 최종 결과가 기존과 동일하게 동기화된다.
6. STL 바이너리 수정 없이 렌더링 좌표와 물리 좌표가 하나의 레이아웃 데이터로 관리된다.

## 8. 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| 고속 주사위가 진입판 또는 바닥을 통과함 | 두꺼운 Box 바닥, 속도 상한, 고정 스텝/서브스텝 유지 |
| 보드 림을 시각적으로 관통함 | 림 최고점과 형상 지지 반경을 반영한 포물선 최소 높이 보장 |
| 진입 중 6시 벽이 너무 빨리 닫힘 | 모든 대상 주사위의 중심과 후면 여유까지 통과한 뒤 일괄 전환 |
| 천장이 투척 호를 막음 | `INGRESS`에서 천장 제거 또는 상향, 진입 완료 후 복구 |
| 리사이즈가 굴림 중 경계를 초기화함 | 현재 경계 모드를 보존해 재생성하거나 굴림 종료까지 재생성 지연 |
| STL 로딩 전에 굴림이 시작됨 | 레이아웃·충돌판 준비 완료 Promise 이후 버튼 활성화 |
| 외부 시작이 화면에서 잘 읽히지 않음 | 우선 화면 밖 진입을 적용하고 필요할 때만 트레이 채움 비율 소폭 조정 |

## 9. 승인 후 첫 구현 단위

승인 후에는 먼저 `YachtTrayModel`의 실측 좌표 계약과 `DiceEngine`의 보드 물리판을 구현하고, 디버그 표시로 겹침이 해소되는지 확인한다. 이 기반이 검증된 뒤 외부 진입 상태와 투척 궤적을 붙인다. 좌표 불일치를 먼저 제거해야 연출 튜닝 수치가 리사이즈나 STL 배율 변화에 따라 다시 깨지지 않는다.

## 10. 구현 결과

- STL 바이너리 수정 없이 실측 레이아웃과 Cannon 충돌 프록시를 결합했다.
- 평상시 `NORMAL`, 외부 투입 `INGRESS`, 판 뒤집기 `FLIP` 경계를 분리했다.
- 6시 방향 외부 진입판과 두 줄 엇갈림 투척 궤적을 구현했다.
- 모든 주사위가 안쪽으로 들어오면 진입판을 제거하고 6시 방향 벽과 천장을 복구한다.
- 1.6초의 물리 시뮬레이션 시간 안에 진입하지 못한 주사위에는 안전 복구를 적용한다.
- 5개 킵 포켓의 실측 표면 Y를 사용해 킵 주사위 높이를 보정했다.
- STL과 충돌판 준비 완료 후에만 게임 및 랜딩 굴림을 활성화한다.
- 굴림 강제 종료 시간을 벽시계가 아닌 누적 물리 시뮬레이션 시간으로 변경했다.

검증 결과:

- 프로덕션 Vite 빌드 성공
- 일반 D6 5개, D6/D8/무거운 주사위 혼합 6개, D8 1개를 각각 100회 시뮬레이션
- 총 300회에서 이탈, 추락, 비정상 좌표 0회
- 브라우저에서 6시 방향 진입, 보드 안착, `INGRESS → NORMAL` 복구 확인
- 굴림 종료 후 정적 충돌체가 정상 상태의 6개로 복구되는 것 확인
- 브라우저 콘솔 오류 0건
