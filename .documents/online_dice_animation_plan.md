# 온라인 권위 주사위 애니메이션 단일 소유권 전환 계획

- 작성일: 2026-07-31
- 상태: 코드 구현 및 자동 검증 완료, 온라인 수동 확인 필요함
- 범위: 온라인 매치의 투척 종료·결과 표시·정렬만 변경함
- 결과값·프리셋 선택은 서버가 권위로 확정하고, 클라이언트는 수신한 프리셋만 재생함.

## 문제

온라인 투척 종료 시 `forceRollEnd()`, `arrangeAll()`, 별도 키프레임 RAF가 같은 주사위 mesh의 위치와 회전을 동시에 변경함. 물리 프레임 고정, 서버 결과 면 불일치, 정렬 시작점 도약이 발생함.

## 구현 방식

온라인 경로를 `THROW → SORT → IDLE` 상태로 관리함.

1. `THROW`: 서버가 확정한 프리셋 인덱스·반전 여부·시작 시각·결과값을 두 클라이언트에 함께 전송함. 클라이언트는 서버 시작 시각 기준으로 같은 프레임부터 재생하고 마지막 quaternion을 결과 면에 맞춰 보정함.
2. `SORT`: 착지한 면과 회전을 그대로 고정하고 위치만 정렬 좌표로 이동함.
3. `IDLE`: 정렬이 끝난 뒤 로컬 보간과 입력을 다시 허용함.

`SORT` 중에는 물리 동기화와 기존 `arrangeAll()` 보간이 mesh를 갱신하지 못하게 함. 서버의 ID·값 순서를 그대로 유지해 주사위를 연결하며, 정렬은 결과 면 회전을 바꾸지 않고 위치만 이동함.

## 변경 파일

- `src/DiceEngine.js`: 온라인 상태·단일 RAF·취소 처리를 구현함.
- `src/main.js`: 기존 `forceRollEnd → animateAuthoritativeKeyframes` 연결을 단일 완료 메서드로 교체함.
- `tests/onlineDiceAnimator.test.mjs`: 결과 표시와 정렬 구간 보간을 검증함.
- `bug_logs.md`: 원인과 수정 결과를 기록함.

## 검증

- 모듈 보간 테스트를 실행함.
- 서버 권위 및 게임 권위 테스트를 실행함.
- 프로덕션 빌드를 실행함.
- 실제 두 브라우저 온라인 매치에서 투척 마지막 면, 서버 결과, 정렬 위치가 연속적으로 일치하는지 수동 확인 필요함.

## 구현 결과

- 기존 `externalAnimationActive`와 `animateAuthoritativeKeyframes()` 경로를 제거함.
- `targetValues`를 값순으로 재정렬하지 않아 서버 ID와 결과값 연결을 보존함.
- 투척은 프리셋 원본 quaternion을 유지하고, `completeAuthoritativeRoll()`이 오름차순 정렬 이동과 서버 결과 면 회전을 함께 처리함.
- 새 권위 애니메이션이 시작되거나 주사위 상태가 재생성되면 이전 RAF를 토큰으로 취소함.
- 정렬은 착지 뒤 500ms 타임라인에서만 서버 결과 면 회전과 위치 이동을 수행함.
