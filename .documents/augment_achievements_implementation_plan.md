# 증강 도전과제 구현 계획

## 1. 범위

- 기준 문서: `.documents/augment_achievements_idea.md`
- 구현 대상: 현재 문서에 실제로 적힌 도전과제 48개
- 문서 머리말의 전체 개수 선언은 범위 산정에 사용하지 않는다.
- 기존 증강 마스터리와 기존 특수 도전과제는 유지한다. 단, 아래 대체 대상은 기존 ID를 재사용한다.
- `src/augments.json`에는 도전과제 조건이나 내부 상태를 추가하지 않는다.
- 모든 도전과제 설명 문장은 `~하세요`형으로 끝낸다.
- 도전과제 진행도는 게임이 정상적으로 끝났을 때만 계수한다.
- 핫시트와 증강 핫시트에서는 도전과제를 계수하지 않는다.

## 3. 데이터 계약

도전과제 정의는 `src/augmentProgress.js`에서 관리한다.

```js
{
  id: 'augmentId-slug',
  augmentId: 'augment-id',
  name: '표시 이름',
  description: '달성 조건',
  target: 1
}
```

경기 중 누적값은 기존 `augmentProgressSession`을 확장해 보관한다.

```js
{
  achievements: { [achievementId]: number },
  flags: { [flagKey]: boolean },
  achievementState: {
    scoreEvents: [],
    augmentUses: {},
    phaseScratched: false,
    tableFlip: null
  }
}
```

- 영구 진행도: 기존 `recordAchievementProgress()`와 `saveAugmentProgress()` 사용
- 경기 중 달성값: `achievementState`와 `session.achievements`에 임시로만 누적
- 한 경기 복합 조건: `achievementState`에만 저장하고 경기 종료 시 판정
- 저장 중복 방지: 기존 `augmentStatReceipts/{matchSessionId}` 트랜잭션 사용
- 완료 시각과 목표 상한: 기존 저장 로직 사용
- 이전 사용자 데이터: 기존 ID 재사용 항목은 진행도 보존, 신규 ID는 0부터 시작

### 3.1 정상 종료 계약

다음 조건을 모두 만족해야 `saveAugmentProgress()`를 호출한다.

- 12라운드와 허용된 추가 턴이 모두 끝나 최종 점수가 확정됐음
- 서버 권위 경기에서는 정상 종료 상태를 수신했음
- 참가자 중 누구도 기권하지 않았음
- 연결 종료, 방 이탈, 경기 취소, 강제 초기화로 끝난 경기가 아님
- 로컬 사용자가 정상 참가자로 남아 있음

조건을 만족하지 않으면 경기 중 임시 누적값 전체를 폐기한다. 상대방 기권으로 얻은 승리도 도전과제에 반영하지 않는다.

## 4. 이벤트 수집 지점

### 4.1 점수 기입

`lockScore()`에서 점수가 확정되기 직전 다음 스냅샷을 한 번 만든다.

```js
{
  player,
  round: currentRound,
  categoryId: catId,
  diceValues,
  diceTypes,
  rollsUsed: 3 - rollsLeft,
  baseScore: scoreObj.score,
  bonus: scoreObj.bonus || 0,
  bonusDetails: scoreObj.bonusDetails || [],
  activeAugmentIds
}
```

동일 스냅샷을 점수형·주사위형·연속형 조건에 재사용한다. 점수 계산을 다시 호출하지 않는다.

### 4.2 퀘스트 완료

`updateQuestProgress()`에서 보상 플래그가 `false → true`로 바뀌는 순간만 기록한다. 기존 퀘스트 상태를 다시 계산하지 않는다.

### 4.3 증강 사용

- 판 뒤집기: 버튼 사용 직전에 라운드, 열세 여부, 재굴림 주사위 수 기록
- 등가교환: 실제 추가 굴림이 승인될 때 해당 턴 사용 여부 기록
- 프로모션 주사위: 6 눈금 소모 시 기록
- 요트 뱅크: 15점 확정 기입 시 기록

### 4.4 경기 종료

`savePersonalAugmentProgress()`에서 정상 종료 여부를 먼저 검사한다. 정상 종료일 때만 승패 결합 조건과 미달성 종료 조건을 기록하고 기존 트랜잭션으로 저장한다.

## 7. 구현 순서

1. 정의 48개와 기존 ID 대체 계약 추가
2. 점수 스냅샷 생성과 즉시 판정 추가
3. 복합 조건용 세션 상태 추가
4. 퀘스트 완료 전환 지점 연결
5. 증강 사용 이벤트 연결
6. 경기 종료 승패·미소모 조건 연결
7. 단위 테스트와 기존 도전과제 회귀 테스트
8. 온라인 2계정으로 저장 영수증·중복 방지 확인

## 8. 검증 기준

- 문서의 48개 도전과제가 각각 하나의 정의와 판정 경로를 가진다.
- 기존 ID 대체 5개의 저장 진행도가 초기화되지 않는다.
- 한 점수 기입에서 같은 도전과제가 두 번 증가하지 않는다.
- 본인 또는 상대방 기권, 중단, 취소, 비증강 모드, 비로그인, 로컬 게임은 저장하지 않는다.
- 재접속·권위 상태 재적용·중복 종료 메시지로 진행도가 중복되지 않는다.
- 완료한 도전과제의 `completedAt`은 이후 저장에서 바뀌지 않는다.
- 전체 도전과제 모달과 증강 도감 상세에 같은 정의가 표시된다.
- `node tests/augmentProgress.test.mjs`와 신규 규칙 테스트가 통과한다.

## 9. 구현 전 상태

구현 완료함.

- `src/augmentAchievements.js`에 정의와 공용 점수·종료 판정을 추가했음.
- 로컬 및 권위 서버 점수 이벤트를 모두 연결했음.
- 참가자 기권이 하나라도 있으면 진행도 저장을 건너뛰도록 적용했음.
- 신규 도전과제·기존 진행도·권위 서버·빌드 검증을 완료했음.
