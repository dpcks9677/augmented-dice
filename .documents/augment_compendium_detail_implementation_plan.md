# 증강 도감 상세 정보·통계·도전과제 구현 계획서

- 작성일: 2026-07-30
- 상태: 구현 완료
- 대상: 증강 도감, 계정별 증강 통계, 도전과제 UI·진행도
- 비대상: 증강 효과 및 밸런스 변경, STL/주사위 엔진, 일반 요트 다이스 모드

## 1. 목표

증강 도감에서 증강 카드를 선택하면 해당 증강의 설명, 계정 통계, 관련 도전과제를 하나의 상세 화면으로 보여준다.

상세 화면은 다음 세 카드로 구성한다.

1. 증강 카드: 기존 도감 카드와 동일한 디자인·크기
2. 통계 카드: 증강 카드와 동일한 크기
3. 도전과제 카드: 증강 카드 너비의 1.5배, 증강 카드와 통계 카드의 높이 및 중간 여백을 합친 높이

## 2. 현재 구조와 선행 문제

- `src/views/game.html`의 `modal-compendium`은 카테고리 탭과 카드 목록만 제공한다.
- `renderCompendiumAugments()`는 카드를 생성하지만 클릭·선택 상태가 없다.
- `modal-achievements`는 안내 문구만 있으며 공용 도전과제 행 컴포넌트가 없다.
- 경기 종료 저장은 `stats.augmentStats`에 증강별 등장·채택·완주 통계를 누적한다.
- 현재 경기 기록 저장은 대표 클라이언트가 수행하며, 다른 참가자의 계정 통계 갱신 경로가 없다.
- 등장 횟수와 증강별 능력 지표를 수집하는 세션 데이터가 없다.

따라서 상세 UI보다 먼저 증강 식별자와 계정별 통계 저장 계약을 확정해야 한다.

## 3. 사용자 흐름

### 3.1 목록 상태

- 기존 카테고리 탭과 4열 카드 목록을 유지한다.
- 사용 가능한 증강 카드는 버튼 역할을 갖고 마우스, Enter, Space로 선택 가능하게 한다.
- 리워크 예정 카드는 기존 비활성 표현을 유지하되 상세 설명 열람은 허용한다.

### 3.2 상세 진입

1. 사용자가 증강 카드를 선택한다.
2. 선택 카드의 위치와 크기를 측정한다.
3. 나머지 목록은 `opacity`와 작은 `scale`로 정리한다.
4. 선택 카드는 상세 화면의 좌측 상단 위치로 이동·확대된다.
5. 통계 카드는 아래에서, 도전과제 카드는 오른쪽에서 짧은 지연을 두고 나타난다.
6. 포커스는 상세 제목 또는 뒤로가기 버튼으로 이동한다.

권장 전환 시간:

- 선택 카드 이동: 280ms
- 나머지 목록 정리: 180ms
- 통계·도전과제 카드 등장: 220ms, 40ms 간격
- 이징: `cubic-bezier(0.22, 1, 0.36, 1)`

View Transition API를 사용할 수 있으면 선택 카드에만 적용하고, 미지원 브라우저는 동일한 CSS transform 전환을 사용한다. `prefers-reduced-motion: reduce`에서는 이동 애니메이션을 제거하고 즉시 전환한다.

### 3.3 상세 종료

- 상세 화면에 “도감으로 돌아가기” 버튼을 둔다.
- Escape는 상세 화면을 목록으로 먼저 복귀시키고, 목록 상태에서 다시 누르면 모달을 닫는다.
- 복귀 시 기존 카테고리, 스크롤 위치, 선택 카드 포커스를 복원한다.

## 4. 상세 레이아웃

데스크톱 상세 그리드:

```text
┌──────────────┬───────────────────────┐
│  증강 카드   │                       │
│    1.0W      │    도전과제 카드      │
├──────────────┤       1.5W            │
│  통계 카드   │                       │
│    1.0W      │                       │
└──────────────┴───────────────────────┘
```

CSS 계약:

```css
.compendium-detail {
  display: grid;
  grid-template-columns: minmax(0, 2fr) minmax(0, 3fr);
  grid-template-rows: repeat(2, var(--compendium-card-height));
  gap: var(--compendium-detail-gap);
}
```

- 증강 카드: `grid-column: 1; grid-row: 1`
- 통계 카드: `grid-column: 1; grid-row: 2`
- 도전과제 카드: `grid-column: 2; grid-row: 1 / 3`
- 도전과제 카드 높이는 두 행과 중간 gap의 합으로 자동 결정한다.
- 900px 이하에서는 세 카드를 한 열로 배치하며 도전과제 카드는 내용에 따라 높이가 늘어난다.
- 600px 이하에서는 모달 전체를 세로 스크롤하고 카드 내부 이중 스크롤을 피한다.

## 5. 카드별 정보

### 5.1 증강 카드

- 카테고리
- 아이콘
- 증강 이름
- 상세 설명
- 대상 족보 또는 발동 대상
- 사용 가능/리워크 상태

기존 도감 카드 마크업을 공용 렌더 함수로 분리해 목록 카드와 상세 카드가 같은 내용을 사용하도록 한다.

### 5.2 통계 카드

모든 증강의 기본 통계:

- 등장 횟수: 완주한 경기에서 해당 계정의 선택지로 표시된 횟수
- 채택 횟수: 등장 선택지 중 직접 선택 또는 제한시간 자동 선택된 횟수
- 채용률: `채택 횟수 / 등장 횟수 × 100`

채용률은 저장하지 않고 렌더링 시 계산한다. 등장 횟수가 0이면 `0%`로 표시한다.

증강별 추가 통계는 정의된 항목만 표시한다.

- 발동 횟수
- 성공/완료 횟수
- 추가 획득 점수 합계
- 사용 횟수 및 잔여 사용량 소비
- 해당 증강 족보의 최고 점수

모든 증강에 모든 항목을 저장하지 않는다. 증강 속성과 실제 이벤트에 맞는 지표만 `augmentTelemetryDefinitions`에 등록한다.

### 5.3 도전과제 카드

도전과제 모달과 상세 카드가 같은 `renderAchievementItem()` 컴포넌트를 사용한다.

행 구성은 왼쪽부터 다음 순서로 고정한다.

1. 아이콘: 48×48px. 전용 아이콘이 없으면 해당 증강 아이콘을 대체 이미지로 사용한다.
2. 본문: 도전과제 이름을 위에, 클리어 기준을 아래에 배치한다.
3. 진행도: 컨테이너 제일 오른쪽에 고정한다. `n/m` 숫자 표시를 위에, progress bar를 아래에 배치한다.
4. 완료 시각: 도전과제를 완료하면 진행도 컨테이너를 완료일·시간 컨테이너로 교체하고 `yyyy.mm.dd am/pm nn:mm에 달성` 형식으로 표시한다.

특정 조건 달성형 도전과제처럼 수치 진행도가 없는 경우 progress bar는 출력하지 않는다.

Steam 도전과제는 레이아웃만 참고한다. 색상, 테두리, 그림자, 타이포그래피는 프로젝트의 기존 모던 디자인 톤을 따른다.

접근성:

- 행은 `aria-label`에 이름·조건·진행도를 포함한다.
- 진행 바는 `role="progressbar"`와 `aria-valuenow`, `aria-valuemax`를 사용한다.
- 아이콘만으로 달성 여부를 전달하지 않는다.

## 6. 기본 도전과제: 증강 마스터리

모든 증강에 다음 도전과제를 자동 생성한다.

- ID: `augment-mastery:{augmentId}`
- 이름: `[증강이름] 마스터리`
- 기준: 해당 증강을 선택하고 게임을 끝까지 10회 플레이
- 목표값: 10
- 진행값: `completedSelections`
- 완료 조건: `completedSelections >= 10`
- 아이콘: 해당 증강 아이콘을 재사용하고 마스터리 테두리를 추가

집계 규칙:

- 로그인 계정만 진행된다.
- 증강 모드의 완주 경기만 인정한다.
- 제한시간 자동 선택도 채택으로 인정한다.
- 해당 플레이어가 기권하면 인정하지 않는다.
- 다른 플레이어의 기권으로 경기가 끝나더라도 본인이 기권하지 않았으면 인정한다.
- 한 경기에서 같은 증강은 최대 1회만 증가한다.
- 리워크 예정 증강은 기존 진행도를 보존하되 신규 진행은 발생하지 않는다.

## 7. 데이터 모델

사용자 문서의 `stats.augmentStats`와 `achievements`에 진행도를 저장한다.

```js
users/{uid} {
  stats: {
    augmentStatsVersion: 1,
    augmentStats: {
      [augmentId]: {
        appearances: 0,
        selections: 0,
        completedSelections: 0,
        metrics: {
          [metricKey]: 0
        },
        updatedAt
      }
    }
  },
  achievements: {
    ["augment-mastery:" + augmentId]: {
      progress: 0,
      target: 10,
      completed: false,
      completedAt: null
    }
  }
}
```

`favoriteAugments` 호환 경로는 2026-07-31 전체 기록 초기화와 함께 제거했다. 증강 선택 통계의 단일 원천은 `stats.augmentStats`이다.

## 8. 경기 중 수집 로직

경기 세션에 계정별 임시 수집기를 둔다.

```js
augmentTelemetry[playerIndex] = {
  draftReceipts: new Set(),
  appearances: {},
  selections: {},
  metrics: {}
};
```

### 8.1 등장 기록

- 실제 본인 선택 모달이 처음 표시될 때 세 선택지를 기록한다.
- 영수증 키는 `{matchSessionId}:{round}:{playerIndex}`로 만든다.
- 재접속·재렌더링으로 같은 모달이 다시 열려도 한 번만 기록한다.
- 관전자에게 표시된 상대 선택지는 해당 관전자의 통계에 기록하지 않는다.

### 8.2 채택 기록

- 클릭 선택과 자동 선택이 확정되는 공통 함수에서 기록한다.
- 네트워크 메시지 수신과 UI 재렌더링은 중복 집계하지 않는다.

### 8.3 추가 지표 기록

증강 효과가 실제 발생하는 지점에서 다음 형태의 이벤트를 수집기에 전달한다.

```js
recordAugmentMetric(playerIndex, augmentId, metricKey, amount);
```

허용된 `metricKey`는 `augmentTelemetryDefinitions`에 선언한다. 임의 키를 Firestore에 저장하지 않는다.

예시:

```js
{
  "table-flip": [
    { key: "uses", label: "판 뒤집기 사용 횟수", aggregate: "sum" }
  ],
  "yacht-bank": [
    { key: "completed", label: "저금 완료 횟수", aggregate: "sum" },
    { key: "bankedScore", label: "누적 저금 점수", aggregate: "sum" }
  ]
}
```

## 9. 저장과 동기화

경기 기록 저장과 개인 진행도 저장을 분리한다.

- 경기 문서: 기존처럼 대표 클라이언트가 1회 저장
- 개인 증강 통계: 모든 인증된 참가자가 자신의 계정 문서만 저장

완주 시 현재 계정의 세션 수집값을 Firestore transaction으로 누적한다. 기존 `stats`의 알 수 없는 필드를 삭제하지 않도록 `...oldStats`를 보존한다.

중복 저장 방지:

- 경기 시작 시 공유 `matchSessionId`를 만든다.
- `users/{uid}/augmentStatReceipts/{matchSessionId}` 존재 여부를 transaction에서 확인한다.
- 영수증이 있으면 통계·도전과제 갱신을 건너뛴다.
- 통계 갱신과 영수증 생성은 같은 transaction에서 처리한다.

Firestore 규칙은 로그인 사용자가 자신의 통계와 영수증만 읽고 쓸 수 있도록 제한한다.

## 10. 공용 도전과제 컴포넌트

도전과제 정의와 진행 데이터를 분리한다.

- 정의: ID, 이름, 설명, 아이콘, 목표값, 관련 증강 ID
- 진행: 현재값, 완료 여부, 완료 시각

렌더 함수:

```js
renderAchievementItem(definition, progress)
renderAchievementList(container, definitions, progressMap)
```

사용처:

- 전체 도전과제 모달: 모든 정의 표시
- 증강 상세 도전과제 카드: `augmentId`가 같은 정의만 표시

초기 구현에서는 모든 증강의 마스터리만 제공한다. 이후 전용 도전과제를 추가해도 컴포넌트와 저장 구조는 유지한다.

## 13. 검증 계획

기능:

- 카드 클릭, Enter, Space로 상세 진입
- 뒤로가기와 Escape로 목록 상태 복원
- 카테고리와 스크롤 위치 유지
- 기본 통계와 증강별 추가 통계 표시
- 전체 도전과제 모달과 증강 상세가 동일한 행 컴포넌트 사용

집계:

- 같은 선택 모달 재렌더링 시 등장 횟수 중복 없음
- 클릭·자동 선택 모두 채택 횟수 1 증가
- 기권한 계정은 마스터리 완주 횟수 증가 없음
- 정상 완주 10회에서 마스터리 1회 달성
- 저장 재시도·재접속 후 같은 `matchSessionId` 중복 없음
- 두 계정 모두 자신의 통계가 갱신됨

UI:

- 데스크톱에서 좌측 카드 너비와 우측 카드 너비가 정확히 1:1.5
- 좌측 두 카드와 gap의 합이 우측 카드 높이와 일치
- 900px/600px 구간에서 잘림과 이중 스크롤 없음
- 키보드 포커스가 모달 밖으로 이탈하지 않음
- 모션 감소 설정에서 애니메이션 없이 정보 접근 가능

## 14. 완료 기준

- 증강 카드 선택 시 상세 정보·통계·관련 도전과제가 한 화면에 표시된다.
- 통계는 완주 경기 기준으로 정확하고 중복 없이 누적된다.
- 모든 증강에 `[증강이름] 마스터리`가 자동 생성된다.
- 마스터리는 해당 증강을 선택하고 10회 완주한 계정에서 달성된다.
- 도전과제 모달과 도감 상세가 같은 컴포넌트를 사용한다.
- 데스크톱·모바일·키보드·모션 감소 환경을 모두 지원한다.
