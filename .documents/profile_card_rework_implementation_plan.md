# 프로필 카드 리워크 구현 계획서

- 작성일: 2026-07-30
- 상태: 구현 완료, 로그인 2계정 수동 QA 잔여
- 범위: 프로필 사이드바 축소, 프로필 상세 모달, 모드별 통계 표시 기반
- 제외: 레이팅 산정·증감·이력 시스템, 유저 검색 UI, 빈 통계 카드의 실제 콘텐츠

## 1. 목표

현재 좌측 프로필 영역을 유지하면서 프로필 상세 정보와 모드별 통계를 별도 모달로 확장한다.

- 좌측 프로필 카드는 아바타, 닉네임, 상태 메시지만 유지한다.
- 가입일, 플레이 횟수, 조회수 표시 창은 제거한다.
- `createdAt`, `profileViews` 데이터 수집 필드는 삭제하지 않는다.
- 프로필 카드 우상단의 Lucide `circle-plus` 버튼으로 상세 프로필 모달을 연다.
- 프로필 모달은 프로필, 빈 통계, 최근 매치, 모드별 통계의 4종 콘텐츠를 표시한다.
- 본인 프로필 모달에서만 `프로필 편집` 버튼을 제공한다.
- 기존 좌측 `history-card`는 유지한다.
- 기존 history의 프로필 사진에서 타인 프로필 미리보기와 상세 모달 진입을 제공한다.

## 2. 확정 레이아웃

넘버패드 1~6을 아래처럼 해석한다.

```text
┌──────────────┬──────────────┬──────────────────┐
│ 4 프로필     │ 5 통계       │ 6 최근 매치      │
│              │ (공백)       │                  │
├──────────────┴──────────────┤                  │
│ 1~2 게임 모드 통계          │ 3 최근 매치      │
└─────────────────────────────┴──────────────────┘
```

- 4: 기존 프로필 카드
- 5: 제목과 카드 외형만 있는 빈 통계 카드
- 6→3: 하나의 최근 매치 카드가 우측 두 행을 세로 병합
- 1→2: 하나의 게임 모드 통계 카드가 좌측 두 열을 가로 병합
- 모달 크기와 상단 액션 위치는 증강 도감 확장 화면을 재사용한다.
- 900px 이하에서는 `프로필 → 통계 → 게임 모드 통계 → 최근 매치` 순서의 단일 열로 전환한다.

## 3. 좌측 프로필 카드 변경

### 제거

- `.profile-user-detail`의 가입일, 플레이 횟수, 조회수 UI
- 기존 헤더 우측의 아이콘형 프로필 편집 버튼
- 제거된 수치 UI용 스켈레톤 처리

### 유지

- 로그아웃 버튼
- 아바타, 닉네임, 상태 메시지
- 좌측 사이드바의 기존 `.history-card`와 현재 기능
- `createdAt`, `profileViews`, 현행 `stats.modes`·`stats.augmentStats` 데이터
- 아바타 크롭 및 상태 메시지 편집 로직

### 추가

- 프로필 카드 내부 우상단 `circle-plus` 버튼
- 접근 가능한 이름: `프로필 상세 열기`
- 키보드 `Enter`/`Space`, `focus-visible` 상태 지원
- history 프로필 사진의 hover/focus 미리보기와 클릭 상세 진입

## 4. 프로필 모달

### 모달 구조

- ID: `modal-profile`
- 기존 `.game-modal-overlay`, `.game-modal-content`, 열기·닫기 흐름 재사용
- 최대 크기: 증강 도감과 같은 `85vw × 85vh`, 최대 `1632 × 816px`
- 닫기 버튼, 바깥 영역 클릭, 기존 모달 닫기 정책 지원
- 로딩 중 카드별 스켈레톤, 실패 시 카드 내부 오류 문구 표시

### 프로필 편집 버튼

- 모달 본문의 좌상단에 배치
- 증강 도감 상세의 `← 도감으로 돌아가기` 버튼과 같은 위치·스타일 사용
- 텍스트: `프로필 편집`
- `targetUid === currentUser.uid`일 때만 렌더링
- 클릭 시 기존 상태 메시지·아바타 편집 모드 진입
- 저장 완료 후 모달 프로필 카드와 좌측 프로필 카드를 함께 갱신

### 타인 프로필 진입

- 메인 메뉴의 기존 history에 표시되는 프로필 사진을 상호작용 가능한 버튼으로 변경한다.
- 마우스 hover 또는 키보드 focus 시 아바타, 닉네임, 상태 메시지로 구성된 소형 프로필 미리보기 카드를 띄운다.
- 프로필 사진 클릭 시 해당 사용자의 `targetUid`로 상세 프로필 모달을 연다.
- guest 또는 유효한 UID가 없는 플레이어는 미리보기·상세 진입을 제공하지 않는다.
- 미리보기는 `.history-card`의 `overflow`에 잘리지 않도록 `body` 하위 fixed 레이어에 렌더한다.
- 포인터가 빠르게 지나갈 때 깜박이지 않도록 짧은 열기 지연을 사용하고, 미리보기와 사진 양쪽에서 벗어나면 닫는다.
- 터치 환경은 hover 미리보기 없이 탭으로 상세 모달을 연다.
- 조회한 사용자 데이터는 세션 메모리 `Map`에 캐시하고 history 새로고침 시 재사용한다.
- 타인 상세 프로필을 처음 연 시점에 `profileViews`를 1 증가시킨다. 본인 조회와 같은 브라우저 세션의 동일 사용자 재조회는 제외한다.
- 유저 검색 기능과 검색 UI는 별도 후속 과제로 둔다.

## 5. 콘텐츠별 세부 규격

### 5.1 프로필 카드 — 4번

- 기존 아바타, 닉네임, 상태 메시지 표시
- 가입일, 플레이 횟수, 조회수는 표시하지 않음
- 타인 프로필을 열 수 있도록 렌더 함수는 `targetUid`를 받게 설계
- 편집 상태는 본인 프로필에만 허용

### 5.2 통계 카드 — 5번

- 카드 제목 `통계`
- 본문은 빈 상태 유지
- 추후 확장을 위한 빈 DOM 컨테이너만 둠
- 임시 가짜 수치와 범용 통계 컴포넌트는 만들지 않음

### 5.3 최근 매치 카드 — 6→3번

- 현재 `history-card`와 같은 최대 20경기, 새로고침, 모드, 플레이어, 점수, 결과, 날짜 표시
- 좌측의 기존 `history-card`를 제거하거나 대체하지 않고, 프로필 모달 안에 동일 기능을 추가한다.
- 기존 `renderHistoryCard()`를 재사용
- 현재 함수의 고정 ID `btn-history-refresh`는 클래스 또는 전달받은 버튼 참조로 바꿔 중복 ID를 방지
- `refreshUserHistory(uid, container)` 형태로 대상 UID와 렌더 위치를 명시
- 타인 프로필에서는 해당 사용자를 기준으로 승/패와 점수를 계산
- 빈 전적·조회 실패 상태를 구분

### 5.4 게임 모드 통계 카드 — 1→2번

카드 내부를 위·아래 두 섹션으로 나누고 사이에 구분선을 둔다.

#### 위: 증강 요트 다이스

왼쪽부터:

1. 기존 증강 모드 아이콘
2. 현재 레이팅과 레이팅 변화 SVG 그래프
3. 채택 횟수 기준 Top 3 증강

Top 3는 `stats.augmentStats[augmentId].selections`만 사용한다. 동률이면 증강 ID 순으로 고정해 화면 흔들림을 막는다.

#### 아래: 일반 요트 다이스

왼쪽부터:

1. 기존 일반 모드 아이콘
2. 현재 레이팅과 레이팅 변화 SVG 그래프
3. 최고 득점과 달성일
4. 상단 보너스 달성 횟수
5. 요트 기입 횟수

날짜 형식은 기존 프로젝트 표기와 맞춰 `yyyy.mm.dd`를 사용한다.

## 6. 레이팅 표시

- 증강·일반 모드 각각 기본값 `500`
- 레이팅 이력이 없으면 500의 수평선과 `레이팅 전적 없음` 표시
- 그래프는 신규 차트 의존성 없이 반응형 SVG로 구현
- 그래프 접근성용 요약 텍스트 제공
- 모드별 데이터는 분리

이번 리워크에서는 레이팅 산정·증감·이력 저장을 구현하지 않는다. 양 모드에 500과 빈 그래프 상태만 표시한다.

프로필 리워크 완료 후 별도 `레이팅 시스템 구현` 과제로 다음을 진행한다.

- 온라인 플레이를 레이팅 경기로 정의
- 승패·무승부·기권·상대 레이팅·K값에 따른 증감 공식
- 모드별 레이팅 이력 저장
- 실제 변화선과 포인트 hover/focus 툴팁
- 필요 시 기간 필터

## 7. 통계 데이터 계약

2026-07-31 전체 기록 초기화 후 구버전 호환용 `stats.gamesPlayed`, `wins`, `losses`, `highestScore`, `averageScore`, `favoriteAugments`는 제거한다. 현재 프로필에 필요한 통계는 `stats.modes`와 `stats.augmentStats`만 사용한다.

신규 모드별 필드 제안:

```js
stats: {
  modeStatsVersion: 1,
  modes: {
    augmented: {
      rating: 500
    },
    normal: {
      rating: 500,
      highestScore: 0,
      highestScoreAt: null,
      upperBonusCount: 0,
      yachtCount: 0
    }
  }
}
```

- 누락 필드는 화면에서 0 또는 500으로 정규화한다.
- 최고 득점 날짜, 보너스 횟수, 요트 횟수는 현재 저장되지 않으므로 향후 온라인 경기 종료 트랜잭션에서 누적한다.
- 보너스 달성은 일반 모드에서 실제 상단 보너스가 부여된 경기당 1회 집계한다.
- 요트 기입은 일반 모드에서 `catId === 'yacht' && isYacht === true`로 요트 조건을 실제 달성해 기입한 경우에만 1회 집계한다. 스크래치 또는 효과로 요트 칸에 점수만 들어간 경우는 제외한다.
- 최고 득점 동률이면 최초 달성일을 유지한다.
- 레이팅 이력 저장 형식은 계산 정책 확정 전 추가하지 않는다.

## 10. 검증 기준

- 가입일·플레이 횟수·조회수 UI가 사라지고 `createdAt`, `profileViews` 저장 필드는 유지됨
- `circle-plus` 클릭과 키보드 조작으로 프로필 모달이 열림
- 데스크톱에서 4/5/6/1/2/3 배치와 병합이 정확함
- 모바일에서 콘텐츠가 겹치지 않고 순차 배치됨
- 최근 20경기, 새로고침, 아바타 크롭, 승패 기준이 기존 전적과 동일함
- 기존 좌측 history가 유지되고 기존 전적 기능에 회귀가 없음
- 로그인 사용자의 history 프로필 사진 hover/focus 시 미리보기가 표시되고 클릭 시 해당 사용자 상세 모달이 열림
- guest 프로필에는 타인 프로필 진입 동작이 없음
- 터치 환경에서는 프로필 사진 탭으로 상세 모달이 열림
- 본인 프로필에서만 `프로필 편집`이 보이고 타인 프로필에서는 DOM상 숨김
- 레이팅 데이터가 없을 때 양 모드 모두 500과 빈 그래프 상태 표시
- 증강 Top 3가 채택 횟수 내림차순으로 안정 정렬됨
- 일반 최고 득점 날짜·보너스·요트 횟수의 구버전 누락값이 안전하게 표시됨
- 기존 로그인, 아바타 편집, 상태 메시지 저장, 모달 닫기, 증강 도감에 회귀 없음
- `npm run build`와 관련 DOM 테스트 통과

## 11. 승인된 추가 사항

- 타인 프로필 조회 시에만 `profileViews`를 1회 증가시키고, 본인 조회·같은 세션 중복 조회는 제외한다.
- 최고 득점·보너스·요트 집계는 최근 20경기에서 역산하지 않고 경기 종료 시 누적 저장한다.

## 12. 확정 사항과 후속 과제

### 확정

- 레이팅 산정·증감은 프로필 리워크 이후 별도 과제로 구현한다.
- history 프로필 사진 hover/focus 시 미리보기, 클릭 시 해당 사용자 상세 프로필 모달을 연다.
- 기존 좌측 history 카드는 유지한다.
- 요트 횟수는 요트 조건을 실제 달성해 기입한 경우만 증가한다.
- 최고 득점 동률은 최초 달성일을 유지한다.
- 레이팅 UI는 실제 기능이 없으므로 양 모드 모두 더미 기준 500점과 빈 변화 그래프로 구현한다.
- 타인 프로필 진입과 조회수 세션 중복 방지를 이번 범위에 포함한다.
- 메인 화면 구조와 기존 history 카드는 유지하고 가입일·플레이 횟수·조회수 행만 제거한다. 확보된 높이는 history 카드에 제공한다.

### 후속 과제

1. 레이팅 시스템 구현
2. 유저 검색 기능 및 검색 UI 설계
3. 프로필 조회수의 서버 권한·어뷰징 방지 강화

## 13. 구현 결과

- 기존 메인 화면과 history 카드를 유지하고 가입일·플레이 횟수·조회수 행만 제거했다.
- 프로필 카드 우상단 `circle-plus`와 4/5/6/1/2/3 병합 레이아웃의 상세 모달을 구현했다.
- 양 모드에 더미 500점과 빈 SVG 그래프를 표시한다.
- history 아바타 hover/focus 미리보기, 클릭 상세 진입, 터치 탭 진입을 구현했다.
- 타인 상세 프로필 최초 조회만 `profileViews`를 1 증가시키고 같은 세션 중복·본인 조회를 제외한다.
- 본인 상세 프로필에서만 편집 버튼과 상태 메시지·아바타 편집을 제공한다.
- 일반 모드 최고 득점·최초 달성일·상단 보너스·요트 조건 달성 횟수를 경기 종료 시 누적한다.
- 기존 통계 객체를 보존해 증강 통계가 경기 통계 저장으로 사라지지 않게 했다.
- 프로필 통계·DOM 계약 테스트, 기존 증강 테스트, production build, Firestore rules dry-run, 데스크톱/모바일 DOM·CSS 및 브라우저 콘솔 검증을 통과했다.
