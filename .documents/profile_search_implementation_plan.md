# 프로필 검색 기능 구현 계획서

- 작성일: 2026-08-02
- 상태: 구현 완료, 실제 Firestore 검색 QA 필요
- 범위: 프로필 편집 버튼 옆 검색 진입 UI, 닉네임 기반 사용자 검색, 검색 결과에서 프로필 상세 열기

## 1. 목표

프로필 편집 버튼 옆에 검색창을 추가해 다른 사용자의 프로필을 닉네임으로 찾고, 기존 프로필 상세 모달을 그대로 열 수 있게 함.

- 본인 프로필 편집 흐름은 변경하지 않음.
- 검색 결과는 기존 `openProfileModal(targetUid)`를 사용함.
- 검색 결과에서 다른 사용자의 편집 버튼은 계속 숨김 처리함.
- 새 사용자 데이터 필드는 추가하지 않음.

## 2. 현재 구조

- `src/views/game.html`: 프로필 상세 모달 하단에 `btn-profile-edit`가 존재함.
- `src/profileController.js`: 프로필 모달 렌더링, 캐시, 검색 결과 프로필 진입에 필요한 `openProfileModal()`을 관리함.
- `src/authEngine.js`: Firestore `users/{uid}` 단건 조회만 제공하며, 닉네임 검색 함수는 아직 없음.
- `src/style.css`: 프로필 모달 및 버튼 스타일이 이미 존재함.
- Firestore 사용자 문서의 검색 대상 필드는 현재 `nickname`, 결과 표시 대상은 `uid`, `nickname`, `avatarUrl`, `statusMsg`임.

## 3. 사용자 흐름

1. 사용자가 프로필 상세 모달의 검색창에 닉네임을 입력함.
2. 입력 이벤트마다 짧은 지연 후 검색을 실행함.
3. 검색 결과 카드가 `profile-modal-grid` 안에 표시되고 해당 카드로 스크롤함.
4. 입력값을 trim하고 길이 제한을 적용한 뒤 Firestore에서 검색함.
5. 결과를 닉네임, 아바타가 있는 목록으로 표시함.
6. 결과 항목을 클릭하거나 키보드로 선택하면 해당 UID로 `openProfileModal(uid)`을 호출함.
7. 검색 결과가 없거나 실패하면 검색 영역 안에서 상태 메시지를 표시함.
8. 프로필 상세 모달로 전환되면 검색 UI 상태를 초기화함.

## 4. 검색 규격

### 입력

- 검색 방식: 닉네임 prefix 검색
- 최소 입력: 1자
- 최대 입력: 30자
- 공백만 입력한 경우 요청하지 않음
- 검색어는 `nickname` 원문 기준으로 처리하며, 결과 렌더링 시 `escapeHtml()`을 반드시 사용함.

### Firestore 쿼리

`users` 컬렉션에서 다음 조건으로 최대 20건을 조회함.

```js
where('nickname', '>=', keyword),
where('nickname', '<=', `${keyword}\uf8ff`),
orderBy('nickname'),
limit(20)
```

- Firestore 복합 인덱스 오류가 발생하면 사용자에게 재시도 메시지를 표시하고 임의의 전체 사용자 다운로드로 대체하지 않음.
- 닉네임 대소문자·초성 검색은 1차 범위에서 지원하지 않음. 필요하면 별도 검색용 필드와 데이터 마이그레이션을 후속 과제로 분리함.
- UID는 검색 결과 DOM에 `data-profile-uid`로만 전달하고, 화면에 노출하지 않음.

## 5. UI/UX 규격

- 위치: `프로필 편집` 버튼 바로 옆.
- 별도 검색 버튼은 두지 않음.
- 검색창 자체를 프로필 편집 버튼 옆 UI로 항상 표시함.
- 검색 결과는 `profile-modal-grid` 내부 별도 결과 카드로 표시함.
- 결과 카드는 내부 목록을 세로 스크롤할 수 있으며 최대 5개 결과를 표시함.
- 입력 뒤 결과 카드로 스크롤함.
- 패널이 모달 경계를 넘을 때는 우측 정렬을 유지하되 화면 밖으로 나가지 않도록 최대 너비와 viewport 보정 규칙을 둠.
- 검색창 왼쪽에는 Lucide `search` 아이콘을 배치함.
- 아이콘은 장식용이므로 `aria-hidden="true"`를 적용하고, 실제 접근성 이름은 input의 label 또는 `aria-label`로 제공함.
- 검색창은 아이콘과 입력 영역이 포함된 하나의 시각적 컨테이너로 구성함.
- 검색 결과는 닉네임과 아바타를 포함한 버튼 목록으로 렌더링함.
- 결과 버튼은 `Enter`/`Space`로 실행 가능해야 함.
- 로딩, 결과 없음, 오류 상태를 각각 구분함.
- 검색 중복 요청은 최신 요청만 반영하도록 요청 번호 또는 AbortController 성격의 상태 토큰을 둠.
- 기존 모달 닫기, 바깥 영역 클릭, `Escape` 동작을 방해하지 않음.
- `prefers-reduced-motion`과 기존 버튼 focus-visible 스타일을 따름.

## 6. 구현 변경점

### `src/views/game.html`

- `btn-profile-edit` 옆에 `btn-profile-search` 추가
- 두 버튼을 `profile-modal-actions` 같은 상대 위치 컨테이너로 묶음
- 검색창, Lucide `search` 아이콘, 결과 카드, 결과 목록, 상태 메시지 추가
- 결과 항목은 동적 생성 영역으로 구성

### `src/authEngine.js`

- `searchUsersByNickname(keyword)` 추가
- Firestore `collection`, `query`, `where`, `orderBy`, `limit`, `getDocs`를 사용함.
- 반환값은 `{ uid, ...data }` 형태의 최소 프로필 정보로 정규화함.
- 실패 시 예외를 호출부에서 구분할 수 있도록 기존 조회 함수와 같은 로깅 정책을 유지함.

### `src/profileController.js`

- 검색 패널 열기·닫기 상태 관리 추가
- 입력 이벤트 기반 검색 실행 함수와 결과 렌더러 추가
- 결과 항목 클릭 시 `openProfileModal()` 호출
- 검색 결과 렌더링에 기존 `renderHistoryAvatar()` 또는 동일한 아바타 처리 로직 재사용
- `resetProfileModal()` 및 프로필 모달 전환 시 검색 상태 초기화
- 검색 결과 데이터 캐시 재사용 여부를 검토하되, 1차 구현에서는 검색 결과 자체를 별도 캐시하지 않음

### `src/style.css`

- 기존 프로필 편집 버튼과 높이가 같도록 검색창 스타일 추가
- 검색창, 검색창의 Lucide 아이콘 영역, 결과 카드, 결과 목록, 상태 메시지, 모바일 배치 스타일 추가
- 결과 카드는 `profile-modal-grid` 전체 열을 사용하고, 결과 목록은 `max-height`와 `overflow-y: auto`로 스크롤함
- 모달 우측 여백이 부족한 경우 패널 너비를 줄이고 viewport 안에 남도록 함
- 기존 프로필 모달의 900px 이하 반응형 규칙 안에 검색 결과 폭과 스크롤 규칙 추가

### `firestore.rules`

- 현재 `users` 문서 읽기 규칙으로 컬렉션 검색이 허용되는지 확인함.
- 허용되지 않으면 공개 검색에 필요한 최소 필드 노출 정책을 먼저 결정한 뒤 규칙을 변경함.
- 규칙 변경 없이 클라이언트에서 우회하거나 전체 사용자 목록을 내려받지 않음.

## 7. 구현 순서

1. Firestore 읽기 규칙과 기존 `users` 문서 구조 확인
2. `searchUsersByNickname()`을 추가하고 쿼리·빈 결과·인덱스 오류를 단위 테스트함
3. HTML에 버튼과 검색 패널 추가
4. `profileController.js`에 상태 관리, 이벤트, 결과 렌더링 연결
5. CSS로 기존 프로필 모달 스타일과 반응형 규칙에 맞춤
6. 검색 결과에서 기존 상세 프로필 모달 진입 검증
7. 게스트·미로그인·로그인 사용자별 접근 동작 확인
8. `npm run build`와 관련 테스트 실행
9. 구현 완료 후 `graphify update .` 실행 및 계획서 상태 갱신

## 8. 검증 기준

- 프로필 편집 버튼 옆에 검색창이 보임.
- 검색어 1자 미만, 공백, 30자 초과 입력이 안전하게 처리됨.
- 정확한 닉네임과 prefix 닉네임 결과가 표시됨.
- 결과 없음·네트워크 실패·Firestore 인덱스 오류 상태가 구분됨.
- 검색 결과 클릭 시 올바른 사용자의 프로필이 열림.
- 다른 사용자 프로필에는 `프로필 편집` 버튼이 노출되지 않음.
- 검색 결과의 닉네임·상태 메시지 등 사용자 입력이 HTML로 실행되지 않음.
- 중복 클릭이나 빠른 연속 검색에서 이전 응답이 최신 결과를 덮어쓰지 않음.
- 모바일 폭, 키보드 탐색, 모달 닫기 동작이 유지됨.
- `npm run build`가 성공함.

## 10. 구현 결과

- `src/views/game.html`, `src/profileController.js`, `src/authEngine.js`, `src/style.css`에 계획된 검색 기능을 반영했음.
- 검색창은 항상 노출되고, 검색 결과는 `profile-modal-grid` 내부 카드에서 열람함.
- 검색 결과는 최대 5개이며 입력 텍스트와의 일치도 기준으로 정렬하고 결과 목록 자체를 스크롤할 수 있음.
- 검색창은 프로필 편집 버튼과 같은 높이, 기존 폭의 1.7배로 조정했음.
- 검색창 왼쪽에 Lucide search SVG를 배치했음.
- `npm run build`, `npm run test:profile-layout`, `npm run test:main-structure` 통과했음.
- 실제 Firestore 인덱스와 권한을 사용하는 검색 QA는 별도 필요함.
