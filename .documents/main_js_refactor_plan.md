# `main.js` 단계적 전면 분해 구현 계획

## 목표

- 현재 6,361줄인 `src/main.js`를 앱 조립과 시작만 담당하는 진입점으로 축소함.
- 프로필, 온라인 대기실, 게임 세션, 게임 메뉴 UI가 각자 상태와 이벤트를 소유하게 함.
- 사용자 동작, 저장 형식, 네트워크 메시지, DOM 구조는 변경하지 않음.
- 새 런타임 의존성을 추가하지 않음.

## 현재 구조와 문제

- `main.js`가 DOM 조회, 인증, 프로필, 매치메이킹, 로비, 권위 서버 상태 반영, 로컬 게임 루프, 점수판, 증강 진행, 모달을 함께 처리함.
- 파일 전역의 가변 상태와 기능 사이 직접 호출이 많아 기능별 테스트와 변경 범위 판단이 어려움.
- Vite 빌드는 통과하지만 단일 초기 번들이 약 1.55MB이며 크기 경고가 있음. 이번 작업은 구조 개선이 우선이며 동적 로딩은 별도 성능 작업으로 남김.

## 구현 방식

1. 공통 기반을 먼저 분리함.
   - HTML 이스케이프, 프로필 식별자 정리처럼 DOM과 무관한 함수를 작은 유틸리티 모듈로 이동함.
   - 앱 셸의 DOM 캐시, 화면 배율, 스켈레톤, 사운드 최초 활성화를 셸 모듈이 소유함.
2. 독립 UI를 분리함.
   - 프로필 조회·편집·히스토리·아바타 UI를 프로필 모듈로 이동함.
   - 설정·도전과제·증강 도감·도움말 모달을 게임 메뉴 모듈로 이동함.
   - 각 모듈은 필요한 외부 함수와 현재 사용자 조회 함수를 생성 시 주입받고 자체 이벤트를 한 번만 연결함.
3. 세션 흐름을 분리함.
   - 로비·매치메이킹·재접속 상태와 타이머를 온라인 세션 모듈이 소유함.
   - 턴·점수·증강·주사위 상태는 게임 세션 모듈이 소유함.
   - 모듈 간 직접 전역 접근 대신 제한된 명령과 상태 조회 함수만 사용함.
4. `main.js`를 조립 진입점으로 정리함.
   - 뷰 마운트 후 모듈을 생성하고, 인증 상태와 세션 전환 이벤트를 연결하고, 초기 화면을 시작함.
   - 브라우저 디버그 호환에 필요한 기존 `window` 필드는 유지함.

## 안전장치

- 함수 이동 단계에서는 동작 변경과 이름 변경을 섞지 않음.
- 네트워크 메시지 이름, Firebase 문서 필드, 로컬 스토리지 키를 그대로 유지함.
- 각 단계마다 `npm run build`를 실행해 순환 import와 누락된 참조를 즉시 잡음.
- 기존 정적 레이아웃 테스트가 `main.js` 구현 문자열에 의존하면 새 소유 모듈을 함께 검사하도록 갱신함.

## 검증

- 기존 7개 테스트 스크립트가 모두 통과해야 함.
- 프로덕션 빌드가 성공해야 함.
- 추가 구조 테스트로 `main.js`가 조립 책임만 갖고, 분리된 모듈이 직접 실행 가능한 ES 모듈인지 확인함.
- 최종 코드 변경 후 `graphify update .`를 실행함.

## 완료 기준

- `main.js`에 도메인 구현 함수와 장기 가변 게임 상태가 남지 않음.
- 각 주요 기능이 독립 파일에서 응집된 상태와 이벤트 수명주기를 소유함.
- 기존 저장·네트워크·UI 동작 계약과 테스트 결과가 유지됨.

## 구현 결과

- `src/main.js`를 기존 공개 export만 전달하는 1줄 진입점으로 축소했음.
- 앱 셸, 프로필, 경기 로그/사이드바, 게임 메뉴/증강 도감, 랜딩 주사위를 독립 모듈로 분리했음.
- 남은 온라인·로컬 게임 상태는 `gameRuntime.js`가 한곳에서 소유하도록 격리했음.
- 구조 회귀 테스트를 추가하고 프로필 정적 테스트의 검사 대상을 새 소유 모듈로 변경했음.
- 프로덕션 빌드와 전체 등록 테스트가 통과했음. 초기 번들 동적 로딩은 이번 구조 개선 범위에서 제외했음.
